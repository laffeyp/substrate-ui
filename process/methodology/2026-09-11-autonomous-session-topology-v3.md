# autonomous_session_topology — a session topology that does not pause for a human

*Design paper, round 3. 2026-09-11. Supersedes v1 and v2, both on disk as audit trail.
v2 was overbuilt. It invented an outer parallel-orchestration topology with N embedded
substrates, cross-slot convergence measurement, and a research programme around
variant runs. That was the wrong frame. The user's idea is one topology, not an
orchestrator over many. The N-copies use case is what a person does with it after it
exists — not part of the design. This paper describes the one topology, and nothing
else.*

---

## 1. What this topology is

A session topology whose user-side turn is generated by the topology itself, not by a
person typing into a shell. It runs the same substrate turn loop
`session_topology` runs — `UserMessage` → `PromptComposed` → `ModelReply` → `Park` →
`UserMessage` again — with one substitution. Where `session_topology` uses
`pause_await_input` to halt after each model turn and wait for a shell to append the
next `UserMessage`, this topology emits the next `UserMessage` itself, from a
Producer inside the topology.

That is the whole design. Everything else in this paper describes how the emitted
`UserMessage` gets chosen so it is useful rather than random.

---

## 2. What changes from session_topology, precisely

`substrate/src/substrate/topologies/session/__init__.py` composes:

- Event schemas: `SessionStarted`, `UserMessage`, `ModelReply`, `Park`, `SessionEnded`,
  `SessionEndRequested`, `SessionWarning`, `PromptFragment`, `PromptComposed`.
- Producers: composer, parent-context, per-turn, role, tools-suite, bundle,
  user-message-fragment, CI/walkthrough dual-mode.
- Termination: an `any_of` that includes `pause_await_input(when=<awaiting user>,
  resume_condition="user_message")`.

The autonomous topology reuses every one of those event schemas and every one of those
Producers unchanged. Two things change:

- **Termination.** `pause_await_input` is dropped. Termination becomes
  `any_of(threshold_count("SessionEnded", 1), quiescence_with_watchdog(seconds=1800))`
  — the run ends when the model emits `SessionEnded` or when nothing has moved in
  thirty minutes.
- **A new Producer, `user_side`, is added.** It is triggered by every `ModelReply`,
  every `Park`, and every `SessionWarning`. Its output is a `UserMessage` — the next
  turn's input. The topology now closes the loop on its own; the shell is not
  required for it to make progress.

Two new views feed the `user_side` Producer:

- `trace_view` — a `KindBuffer` over the session's events since the last `UserMessage`.
- `state_view` — a small deterministic view holding the current sprint pointer, the
  last watcher verdict, and the checkpoint index for the rotation schedule.

That is the whole topology change. No composition, no embedded substrate, no outer
orchestration.

## 3. `user_side` in two halves

`user_side` decomposes into two smaller Producers so each half is separately testable.

### 3.1 `watcher`

A pure function of `(trace_view, state_view, project_files) → Verdict`. Emits one
`WatcherVerdict{verdict, drift_kind, detector_scores}` per firing. Verdict values are
`green`, `yellow`, or `red`.

Five detectors. On any given firing, a subset runs per the rotation schedule below.

- **vocabulary_conformance** — checks the sprint's git diff and the JSONL trace for
  tag names not in `signals/0.1.json § layer_1_lexical`. Score 1.0 means every emit
  matches a ratified schema. Anything less is a mouth-side Emitter hole and is red.
- **sdd_hygiene** — checks that `BLACKBOARD.md` and `KIT_DIARY.md` carry an entry
  for the last closed sprint and that any drift found by the other detectors has a
  proposal filed against it.
- **coding_canon** — runs the linter suite (retyped-literals grep, discriminated-union
  coverage, function-length scan, unused-code finder) on the diff since the last
  verdict.
- **design_lock** — screenshots every state the current sprint's card claims to
  render, region-diffs each against the design lock's PNG in
  `handoff_latest/prototypes/`. Skipped on non-UI sprints.
- **prose_register** — runs the `dellm` skill's checks over every committed markdown
  file the diff touched. Returns the machine-tell fingerprint score.

Rotation:

- Every turn: `vocabulary_conformance`, plus a sprint-close check that reads the card.
- Every second turn: `sdd_hygiene`.
- Every fifth turn: `coding_canon`.
- Every UI-touching sprint: `design_lock`.
- Every markdown-touching turn: `prose_register`.

The rotation lives in `state_view.checkpoint_index`; the trace records which
detectors ran on each firing.

Verdict composition is monotone. Any red detector makes the verdict red; any yellow
without a red makes it yellow; otherwise green.

### 3.2 `dispatcher`

Triggered by every `WatcherVerdict`. Emits one `UserMessage` whose `text` is the next
turn's user prompt and whose `slash_source` field is set to `"dispatcher"` so the
transcript distinguishes a topology-emitted turn from a human-typed one. The
`slash_source` field already exists on `UserMessage` per
`topologies/session/__init__.py:121`.

The dispatcher's behaviour is a rule table, not a program. Three invariants over the
table:

- On any green verdict, emit a `silent_continue` reply — the shortest text that
  keeps the model on task ("continue", "next", "go on", or the empty prompt on the
  paths where the composer accepts one).
- On a yellow verdict, emit the reply whose `drift_kind` matches the verdict's
  `drift_kind`. If none matches, emit a `halt` reply and let termination
  quiescence close the run.
- On any red verdict, emit a `halt` reply carrying the drift detail. The operator
  reads the halted run, ratifies or corrects, and — if resuming makes sense — starts
  a fresh run against the corrected state.

Independent of the verdict, the dispatcher inserts periodic reminders keyed to
detector staleness. If `sdd_hygiene` has not fired in the last five turns, the next
reply prepends "confirm SDD hygiene before continuing." If `design_lock` is stale on
a UI-touching sprint, likewise. This is the mechanised version of the periodic "look
at the designs again" and "remember SDD best practices" prompts observed in the
current session's transcript.

## 4. Where the reply text comes from

The dispatcher's rule table is not designed a priori. Its clusters and its text
templates are mined out of prior successful sessions. The pass runs once, produces a
corpus file, and the topology loads that file as a run baseline.

Pass:

1. Read the transcripts from
   `~/.claude/projects/-Users-peterlaffey-Documents-Claude-Projects-Agent-Orchestration/*.jsonl`.
2. For each transcript, enumerate every operator turn.
3. For each operator turn, record: the prior assistant turn's signal shape (which
   tools it called, which tags fired, which sprint card it referenced), the reply
   text the operator typed, and a hand-assigned label for the intervention kind.
4. Include silent-continue evidence. Every assistant turn the operator did not
   interrupt is a `(signal_shape, "", "silent_continue")` datum. These are the
   majority of turns in a well-run session; without them the corpus over-weights
   correction.
5. Cluster the signal shapes. Each cluster becomes one rule-table entry: which
   verdict shape triggers it, which reply text fires, which intervention kind it
   labels.

The corpus is versioned; the run manifest carries the corpus version so replays are
exact. The corpus contains the operator's writing-style corrections too — the tonal
interventions ("no LLM-speak", "stop preambling", "you are being bizarrely hostile")
map to prose-register drift replies.

Corpus quality dominates dispatcher quality. A thin corpus produces a dispatcher
that hangs often or repeats itself. Scale is the fix: mine more transcripts, refine
clusters, iterate.

## 5. What the topology declares

Under `substrate/src/substrate/topologies/autonomous_session/`:

- `producer_kind("watcher", schemas=[WatcherVerdict], factory=...)`.
- `producer_kind("dispatcher", schemas=[UserMessage], factory=...)`. The dispatcher
  emits `UserMessage` directly into the session's own event stream, so the composer,
  per-turn, and model-reply Producers see it as the next turn's input.
- `view("trace_view", KindBuffer(...))`.
- `view("state_view", <deterministic small struct>)`.
- `view("corpus", <keyed lookup over the mined corpus>)` — loaded from baseline
  metadata, deterministic, read-only after RunStarted.
- `trigger("run_watcher", subscription={ModelReply, Park, SessionWarning},
  starts="watcher", ...)`.
- `trigger("run_dispatcher", subscription={WatcherVerdict}, starts="dispatcher",
  ...)`.
- Every producer_kind and trigger from `session_topology` verbatim.
- `termination(any_of(threshold_count("SessionEnded", 1),
  quiescence_with_watchdog(seconds=1800)))`.

No new kernel primitive. No new termination policy. No composition boundary. The
topology sits alongside `session_topology` in the registry as a sibling, not an
outer wrapper.

## 6. Running the topology

`substrate --topology autonomous_session --manifest run.json`. That is the whole
invocation.

The run manifest names: the workspace, the driver (any Responder — Ollama, CLI
Claude, Deterministic), the sprint queue file, the corpus version, and any
detector overrides.

To run it three times in parallel: open three shells and invoke it three times
against three separate workspaces. That is not part of the topology's design. It is
what a person does with a topology that no longer needs a person watching it.

If a shell wants to visualise a running autonomous session, the existing
substrate-ui pane binds to it exactly as it binds to a manual session — the events
on the bus have identical schemas. The only shell-visible difference is that
`UserMessage.slash_source == "dispatcher"` on the auto-typed turns; the pane can
render those in a muted style to distinguish them.

## 7. What substrate needs

Nothing new. Every primitive is already declared:

- `Producer`, `View`, `Responder` — `substrate/src/substrate/protocols.py`.
- `producer_kind`, `view`, `trigger`, `route`, `termination` — the
  `TopologyBuilder` methods at `substrate/src/substrate/kernel/topology.py:130`.
- `threshold_count`, `quiescence_with_watchdog`, `any_of` —
  `substrate/src/substrate/kernel/policies.py`.
- `UserMessage`, `ModelReply`, `Park`, `SessionWarning` event schemas —
  `substrate/src/substrate/topologies/session/__init__.py`.
- `slash_source: str | None` field on `UserMessage` — same file.

The one design choice worth flagging is that the dispatcher emits `UserMessage`
into the topology's own bus. In `session_topology` today, `UserMessage` is
externally appended by a caller of `SessionRegistry.turn_sync`. Here it comes from
an in-topology Producer. The kernel places no restriction on which Producer emits
which kind, so this is only a convention change; the composer's trigger already
subscribes to `UserMessage` and does not care about its provenance beyond the
`slash_source` field.

## 8. What the topology does not do

- **It does not compose N session topologies.** N sessions running in parallel is
  a person opening N shells. Not part of the topology.
- **It does not measure cross-run convergence.** That is an analysis someone runs
  over N runs' JSONL after the fact. Not part of the topology.
- **It does not ratify vocabulary proposals.** On a red verdict flagging an
  invented tag or a payload-shape refusal, the dispatcher halts and the operator
  ratifies out of band.
- **It does not author sprint cards.** Sprint cards are authored by the model
  under operator direction, elsewhere. The topology consumes the sprint queue as
  input.
- **It does not replace the shell for interactive work.** A person driving a
  session by hand still uses `session_topology` via the substrate-ui bridge. The
  autonomous topology exists for the case where a person does not want to sit and
  type.

## 9. Risks

- **Corpus coverage.** A poor corpus means poor dispatcher replies. Iterate on the
  mining pass; ship a first cut and grow it.
- **Detector false positives.** A watcher that classifies green work as yellow
  halts too often and kills throughput. Every detector needs a small unit-test
  fixture set derived from real transcript excerpts before it goes live.
- **Silent drift.** A drift kind that no detector covers will not be caught. The
  five detectors above are the coverage today. New drift kinds need new detectors,
  which are pure functions and cheap to add.
- **Dispatcher loops.** A dispatcher-model interaction that oscillates between
  yellow and green without progress is possible. The mitigation is a per-sprint
  turn cap in the termination policy: if the sprint pointer does not advance in K
  turns, halt.

## 10. Next steps

1. Run the transcript-mining pass on four to six strong prior sessions. Produce a
   first-cut corpus with cluster labels.
2. Implement each detector as a standalone function under
   `substrate-ui/tools/detectors/`. Unit-test against fixture events.
3. Implement `autonomous_session_topology` in
   `substrate/src/substrate/topologies/autonomous_session/`. Reuse every schema
   and Producer from `session_topology`; add `watcher`, `dispatcher`, the two
   views, the two triggers, and the new termination.
4. Run it against a small sprint queue and a deterministic Responder. Read the
   JSONL. Confirm the dispatcher's silent-continue replies land at the right
   turns and its halts land at the right red verdicts.
5. Swap the deterministic Responder for an Ollama Responder and re-run.

That is the whole plan. A person can then open three shells and run it three times
if that is what they want.

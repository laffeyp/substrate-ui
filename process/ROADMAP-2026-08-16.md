## 1. The next direction — HELD behind workflow parity (substrate-side)

Per `docs/cockpit/SUBSTRATE-UI-NEXT-2026-07-31.md` and `docs/cockpit/WORKFLOW-PARITY-PLAN-2026-07-31.md`: the ten-item substrate-ui-NEXT evolution (skin, movable panes, real PTY, standalone wrapper, language pass, one-session-one-record, transcript view, MCP, provider parity, assay carry) is DEFERRED behind the workflow-parity plan. Workflow parity is substrate-side work (BI-1 delegate → BI-2 MCP → BI-3 manifest → BI-4 workflow library; the doc lists BI-4 first because it needs no engine work).

Substrate-ui's queue when the hold lifts, in the doc's own order:

1. **Language pass + skin** (cheap, high-visibility). White/Orwell filter on every user-facing string; graphite identity from the mock tokens as the default theme; a real light mode; green demoted to meaning (pass, live, prompt).
2. **One-session-one-record + transcript view.** Fix run-per-exchange: a conversation is one record; turns are injected events; the surface appends. Add a dialogue-as-dialogue reading surface (the output is on the record; no transcript pane today).
3. **Movable panes.** Draggable/resizable with persisted layout.
4. **Standalone-wrapper spike.** Thin native shell hosting the web app + supervising the daemon + a first-run session token (Tauri/Electron/native-webview, one-week spike).

Items 5-10 (real PTY, MCP, provider parity, assay carry, thinking capture) land as their prerequisites clear. Every one of these ships in this repo (`substrate-ui`); workflow parity ships in `substrate`.

# substrate-shell — signal vocabulary v0.1 rationale

*Sprint 0 output per sdd-kit-2/grammar/BOOTSTRAP.md § Step 11. Companion to `signals/0.1.json`. Six sections in order: intent + scope, per-layer decisions, dual-contract audit table, project-specific overrides, open proposals for v0.2, signatures.*

---

## Intent and scope

The substrate shell is a reader-AND-controller desktop UI over substrate 1.0.1. It renders every substrate wire kind (kernel lifecycle + session vocabulary + tool_loop) and it CAUSES substrate events through the Python bridge (create_session, turn_sync, interrupt, set_driver, set_bundle, delete). Because it causes events, it locks its own vocabulary — Addendum A9's pure-reader carve-out does not apply (KIT_DIARY H10 confirmed 2026-08-17).

The vocabulary carries the observability contract. Every shell tag emits BOTH as a JSONL log line (Foundation 01 signal types #1 and #8) AND flips a deterministic pixel-anchor testid the harness reads from a screenshot (Addendum A2). The three channels — shell JSONL trace, substrate bridge.log, decoded pixel anchors — must agree on any grade run; disagreement is the bug (Addendum B1). Non-negotiable per Architect 2026-09-08.

Bounds: the vocabulary covers Prototype v7's core daily-driver design lock (sheet turns 15 + 19 + 20). Extensions (turns 16 editor level, 17 contextual modes, 18 mobile) are speculative per D47 and defer to v0.2. Substrate reference entities and their wire strings are named but not owned; the shell reads them, substrate emits them.

The vocabulary v0.1 lands 108 shell tags across 15 categories and four strata, 44 Layer-0 entities (34 shell + 14 substrate reference — where "reference" means the shell renders but does not author), 14 Layer-3 session strata, 34 Layer-4 temporal invariants, 41 Layer-5 state-transition rules, 17 Layer-6 operators across four process boundaries, 15 Layer-7 evidence constraints covering 16 pixel-anchor testids.

## Per-layer decisions

### Layer 0 — Ontology (44 entities)

**What was populated.** 34 shell-owned entities (Window through Anchor) and 14 substrate reference entities (Session through TerminationPolicy). Every entity carries a design citation (v7:LINE, D-NN, FUNCTIONALITY row, PANE-MECHANICS §, or substrate source line).

**What was considered and rejected.** SplitTree as an entity — rejected as a shape over Panes, not a state-carrier. FanOutInline collapsed into DelegateCall with `children_count > 1` — rejected because the walk/descend interactions are shell-only and warrant a first-class shell entity. DelegateInline merged with DelegateCall (substrate) — rejected as DDD bounded contexts (shell owns render/descend, substrate owns wire).

**What was surfaced as v0.2 proposals.** Editor-level modes (Editor, ExplorerRail, MachineryRail, TerminalSill, EditorTab, DocumentSurface, ImageEditor, VideoEditor, AudioEditor, TranslationChip, DesignMode) — twelve entities deferred to v0.2 when turns 16/17/18 ratify. MobileSessionStack + accessory row — v0.2 when D61 sync-only mobile builds.

**Post-review fixes applied.** Pressure-test 2026-09-10: substrate reference set was 10; four topology primitives were missing — Trigger, View, Route, TerminationPolicy (visible in the Structure lens v7:298–312 + Studio form v7:394–411). Added. Count 10 → 14.

**Prior-project postmortem consulted.** substrate-ui KIT_DIARY H10 confirmed: reader-AND-controller UIs get their own vocabulary; the pure-reader carve-out (Addendum A9) does not apply. Every ENTITY_MERGE_PROPOSED handled: DelegateInline ↔ DelegateCall keep separate; FanOutInline ↔ multi-child DelegateCall keep separate.

### Layer 1 — Lexical (108 tags)

**What was populated.** `{ENTITY_SNAKE_UPPER}_{VERB_PAST_PARTICIPLE_UPPER}` throughout. Fifteen categories (window, pane, header, prompt, transcript, reveal, lens, surface, find, descent, dialog, layout, harness, bridge, bridge_reply). Four strata (event 95 / ambient 2 / summary 1 / incident 10). Every tag carries `entity`, `category`, `stratum`, `note`.

**What was considered and rejected.** A per-envelope shell tag mirror of every substrate wire kind — rejected as duplication (substrate owns those kinds; the shell renders them under TRANSCRIPT_ROW_RENDERED × K plus special-shape tags). Passive-render entities emitting tags — rejected; Layer 1 is state transitions, Layer 7's pixel-anchor pairings are the paint witness for passive entities. Seven passive entities carry no emit tag: Assay, DriverChip, Footer, PaneHeader, Records, WindowStrip, WorkspaceChip.

**Post-review fixes applied.**
- Layer 1 review 2026-09-10 P1 (real bug): TRANSCRIPT_PARK_RENDERED.park_reason invented `session_open` — a value not in substrate's ParkReason. Fix: enum trimmed to three values; new tag TRANSCRIPT_AWAITING_FIRST_MESSAGE_RENDERED added as the honest home for the pre-first-turn line (v7:543). Hard rule 2 respected.
- Six gap-fill tags: WORKSPACE_PICKER_WALKED (prompt/event), REVEAL_FOCUS_MOVED (lens/event), TRANSCRIPT_COMPACTED_RENDERED (transcript/event), PROBE_DRIVER_REQUESTED / _PROBED / _FAILED (bridge round-trip).
- Two deferred to v0.2: SESSION_DELETE_* (delete not in the daily-driver design lock; queue when a build sprint wires it) and Assay drill-in (ASSAY_ARM_INSPECTED / ASSAY_CELL_OPENED — when the drill-in path materializes).
- Stratum reclassification: TRANSCRIPT_ROW_RENDERED ambient → event per Foundation 01 (ambient = sampled at high frequency; envelope arrivals are event-cadence).

### Layer 2 — Payload (108 schemas)

**What was populated.** Draft-07 payload schema per tag with closed `additionalProperties`. Envelope pinned: `{t: int ms, kind: UPPER_SNAKE, payload: object}`. ### Layer 6 — Runtime / Operator (17 operators)

**What was populated.** Four process boundaries: renderer (5 ops — ShellReducer, Emitter, AnchorPainter, RecordSubscriber, BridgeClient); renderer preload (1 op — HarnessSink); main (3 ops — BridgeSupervisor, IPCRouter, HarnessLogWriter); bridge (5 ops — HelloEmitter, DispatchLoop, RegistryProxy, DriverResolver, ManifestWatcher); substrate reference (3 ops — SessionRegistry, SessionTopology, DelegateTool). Every LLM call lives inside a substrate.reference Responder; the shell owns none. Model routes named: deterministic (D69 floor) / claude / gemini via CliResponder / any-other via OllamaResponder.

**Halt checks disposed.** 17 ops vs 108 tags — no over-decomposition. Every Layer 1 tag has an emitting operator (programmatically verified).

### Layer 7 — Evidence (15 constraints, 16 pixel-anchors)

**What was populated.** Cross-reference (8 — every `_id` resolves; seed const `""`; driver_params secret-stripping; SETTING_CHANGED oneOf-per-key; every incident carries a diagnostic; PANE_MOVED zone consistency; WORKSPACE_BOUND POSIX path; every envelope_kind traces to a wire kind). **Halt checks disposed.** No incident without diagnostic; no tonal rule unbound; no cross-reference unresolved; no load-bearing state without an anchor (verified against Prototype v7's state-class slot set).

## Dual-contract audit table

Every behavior-category tag pairs with a view-side counterpart — a pixel-anchor testid (Layer 7 pairings) or a DOM element the harness reads directly. All 108 tags paired; 87 via pixel-anchor, 21 via DOM element. One gap surfaced and accepted: `COLLECTION_PERSISTED` writes to SQLite with no visual witness (D68 makes persistence invisible by design; the grader reads the file post-hoc if it needs to grade).

The full pairing table lives in `signals/0.1.json` § `layer_7_evidence.evidence_constraints[pixel_anchor].anchors`. Sixteen testids there paint the bytes the harness decodes; the twenty-one DOM-element pairings live in the WORKING_AGREEMENT § Observation harness (harness scripts read testids by grep against `signals/0.1.json`).

Every incident-stratum tag (10) carries a required diagnostic field (verified against Layer 2 schemas): STUDIO_VALIDATE_FAILED.errors, STUDIO_BUILD_REJECTED.errors, SESSION_CREATE_FAILED.reason, SESSION_RENAME_FAILED.reason, TURN_SUBMIT_FAILED.reason (enumerated 5-way), DRIVER_CHANGE_FAILED.reason, BUNDLE_ATTACH_FAILED.reason, PROBE_DRIVER_FAILED.reason, BRIDGE_DEAD_SURFACED.crash_count, DELEGATE_DEPTH_CAP_REFUSED.depth (const 2).

## Project-specific overrides

- **Strict validator posture.** Every payload has `additionalProperties: false`. Trading System's documentation-only-extras is NOT adopted; the shell is a reader-AND-controller and typos in payload keys are load-bearing bugs.
- **View-payload convention.** The view-side counterpart is a pixel-anchor testid (Layer 7) OR a DOM element read directly, NOT a `SCENE_RENDERED.visible_paths`-style payload field. Non-negotiable per Architect 2026-09-08.
- **Reader-only carve-out inapplicable.** Addendum A9 does not apply — the shell causes substrate events. Confirmed by KIT_DIARY H10 (2026-08-17) reproduced on this project.
- **Tonal canon.** No cost/money display anywhere (D45, D46, WINDOW-STRIP-EXPLORATION §7). No emoji in shell-generated strings (mechanical grep). Labels never wrap (D32; DOM `white-space:nowrap`). No narration prose (D40).
- **Privacy.** Prompt / find text is length-only in payloads. Raw text lives on the substrate record; the shell trace does not duplicate. Secret-carrying keys in driver_params are stripped at emit-time (`/key|token|secret|password/i` regex).
- **Substrate deprecation respected.** SESSION_CREATE_REQUESTED.seed = `const ""` per session_registry.py:421-431.

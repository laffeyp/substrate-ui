## Per-change ledger (what v0.2 adds or renames vs v0.1)

### 1. Category `view` → `pane` (fixes mapping F2)

Substrate's tone canon (`WORKING_AGREEMENT.md § tone canon`) reserves `View` for a runtime primitive: a deterministic RAM-resident projection over the bus. v0.1 used `view` as a category for the browser's panes — same word, two meanings, in the same product. v0.2 renames the category to `pane`. Every tag whose category was `view` now reads `category: "pane"`. `DIFF_RENDERED` (previously `category: "diff"`) also moves to `pane` — it repaints a pane like the other visual tags.

### 2. Tag `VIEW_SWITCHED` → `PANE_SWITCHED` (fixes mapping F2 tag-side)

Sole tag whose name carried "VIEW". Payload keys `to_view` / `prior_view` also rename to `to_pane` / `prior_pane`. Every `emit()` call site in `web/app.ts` updates; the grader's `checkViewSwitchedRender` renames to check `PANE_SWITCHED{to_pane: V}`.

### 3. Structural block `view_payload_universal` → `pane_payload_universal`

Follows change #1. The block's shape (`frame`, `visible`, `pane_id`, `subject_record`) is unchanged. The rename is cosmetic against the block's usage in `pane`-category tags.

### 4. Payload typing — `substrate_kind` foreign key (fixes mapping F3)

`EVENT_INSPECTED.kind` and `PRODUCER_INSPECTED.kind` gain a `payload_types` clause naming the type as `substrate_kind` and `substrate_producer_kind`. Both resolve against `external_vocabulary_ref` — substrate's `signals/0.2.json` tags[].name closed set (for kinds) and substrate's Producer registry (for producer kinds). The emitter does not enforce closed-set validation on these fields yet; the type reference is documentary until a Wave-2 sprint wires substrate's vocab into the loader. The doc reference is the closable end of the retyped-literal drift the mapping review named.

### 5. Declared entity merges (fixes mapping F1)

Top-level `entity_merges[]` names the four Layer-0 entities substrate-ui shares with substrate under different names: Record↔Run, Topology↔Topology, AgentRun↔Run, Event↔Envelope. Each carries a one-line note. Filed per `grammar/PRINCIPLES.md § ENTITY_MERGE_PROPOSED` — the merges are declared, not silent.

### 6. Bridge mapping to substrate's vocabulary (fixes mapping F4)

Top-level `external_vocabulary_ref` names substrate's `../substrate/process/signals/0.2.json` as the external SDK surface substrate-ui reads at runtime, with the two consumer payload fields listed. Matched by a new row in `WORKING_AGREEMENT.md § Canonical home registry` landed in the same session.

### 7. Layer 6 declared (fixes port-plan F14 and mapping F7)

Top-level `runtime_operators[]` names the four browser-side operators v0.1 left unnamed: `SubstrateReader` (the 500 ms poll loop in `followLive`), `SubstrateController` (the launch/resume/agent POST callers), `ReplayEngine` (the rAF loop at STATE.speed), `AgentTurnAccumulator` (streamAgentTurns). Each is tagged `layer: 6` per `grammar/PRINCIPLES.md`. The tags each operator surfaces are noted inline.

### 8. Reworded reader-only framing (fixes mapping F5, F6)

`notes[0]` in v0.1 read "It does NOT try to model the substrate runtime itself." v0.2 rewords: substrate-ui is a "reader AND controller UI over the substrate runtime's records — it reads records via /api/records and CAUSES substrate events via /api/launch, /api/resume, /api/agent." The addendum-A9 pure-reader carve-out doesn't cleanly apply; the honest reading is the reader-plus-controller shape, and the vocab now says so. The invariants that reference `run_name` no longer read as inconsistent with the framing.

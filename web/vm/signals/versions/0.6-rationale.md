# v0.6 rationale — reveal shell vocabulary

v0.6 adds a `picker` category with four tags. The thirty-eight tags of v0.5 carry over unchanged; v0.5 stays as written and locked.

## Why

On 2026-11-05 the user reported that after choosing a folder in a new pane's picker, picking a model sent the picker back to the folder column. The window's signals held nothing about it: the picker's steps (a folder armed, a line entered, the folder dropped, the pane bound) emitted no tag. `DRIVER_PICKED` and `BUNDLE_PICKED` fire, but not the move between columns that the report is about. The kit's Rubber Duck Pass names this a vocabulary gap: a real event happened and the vocabulary had no tag for it.

## The tags (`NEW_TAG_PROPOSED`, ratified)

- `PICKER_FOLDER_ARMED` (`pane_id`, `workspace`, `is_default`, `source`) — `armWorkspace`; `source` is `row`, `dialog` or `typed`.
- `PICKER_FOLDER_DISARMED` (`pane_id`, `cause`) — `disarmWorkspace` and the path box's change; `cause` is `escape`, `arrow_left`, `list_click` or `typed`. This is the kick back, with what caused it.
- `PICKER_LINE_ENTERED` (`pane_id`, `line`, `cause`) — the model, guidance, length and tone lines; `cause` is `picked` or `back`.
- `PICKER_COMMITTED` (`pane_id`, `workspace`, `is_default`) — `commitPane`, summary stratum: the picker's run ends here.

Order: `PICKER_FOLDER_ARMED` precedes any `PICKER_LINE_ENTERED` of the same pane; `PICKER_COMMITTED` follows `PICKER_LINE_ENTERED` with `line` `tone`.

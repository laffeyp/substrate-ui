# v0.67 rationale — a turn acknowledged when the kernel has it

*2026-11-11, sprint 483. Bumps v0.66 to v0.67 (157 tags). One proposal: P-0.67-TURN-ACK. Grounds: a live gate (`editor_follow`, kimi-k2.7-code:cloud) broke T6 on a 13-second turn; the trace showed TURN_ACCEPTED on the server 1 ms after TURN_SUBMITTED, and TURN_ACK only at the turn's end.*

## Layer 4 — Temporal

T6 (TURN_SUBMITTED, then TURN_ACK, TURN_REFUSED or TURN_REFUSED_VIEW_ONLY within 10 s; Nielsen 1993) stays as it is. What changes is when TURN_ACK is written: when the turn's UserMessage reaches the stream (the kernel has accepted and recorded the turn), or when the POST returns if that comes first, once per turn. The POST returns only when the turn ends, because the server runs the turn in `turn_sync` and replies with the record's final seq; a turn has no wall-clock limit, so the POST cannot be the acknowledgement a 10-second rule measures.

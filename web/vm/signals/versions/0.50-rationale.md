# v0.50 rationale — save before send

*2026-11-10, sprint 444. Bumps v0.49 to v0.50 (149 tags). One proposal: P-0.50-SAVE-FOR-SEND. Grounds: the Architect's ruling of 2026-11-10 ("Save every unsaved buffer when a message is sent, before the model starts"); roadmap r13 E10.0; `SAVE-BEFORE-SEND-2026-11-10.md`.*

## Layer 1 — Tags

EDITOR_SAVED_FOR_SEND: a turn's saves of the session's unsaved buffers, made before the turn is posted. One tag per turn, not one per file: the server's FILE_WRITTEN already marks each write, and the record holds each FileWritten with view `send`. Not written when the session had nothing to save, so a turn with no editor work adds nothing to the editor's category.

## Layer 2 — Payload

EDITOR_SAVED_FOR_SEND carries `files` (saves written) and `refused` (saves refused as stale). Neither carries a path (E1). TURN_SUBMITTED gains `saved`, so a turn that saved nothing says so with 0. Without it, a missing EDITOR_SAVED_FOR_SEND could mean either nothing to save or no save step at all.

## Layer 5 — Order

For a pane, EDITOR_SAVED_FOR_SEND precedes the TURN_SUBMITTED of the turn it saved for, and its `files` equals that TURN_SUBMITTED's `saved`. This is stated in the tag's note and checked by the gate `editor_save_on_send.ts` on the packaged trace. No S rule is added. The pair is adjacent in one process's record, so the window's own order is the proof, and no other process takes part.

## Dual-contract pairing

| Behaviour | View-side counterpart |
|---|---|
| A turn posted with unsaved buffers | EDITOR_SAVED_FOR_SEND; FILE_WRITTEN per file; the record's FileWritten view `send` before the UserMessage; the tabs' unsaved dots gone; the activity tab's "saved with the message" |
| A save refused as stale | EDITOR_SAVED_FOR_SEND.refused; the transcript's warning row naming the file; the centre's reload-or-overwrite offer when that file is shown |
| A turn with nothing to save | TURN_SUBMITTED.saved 0 and no EDITOR_SAVED_FOR_SEND |

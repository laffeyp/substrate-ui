## Intent and scope

v0.28 named the editor's tags before the design frames were read, and modelled the editor as one pane's state. Frame 24h draws the editor as a whole-window view beside reveal, and 24a draws one header for it with the "⌘⇧E pane" chip; `web/app/derive/open_view.ts` was written so the editor would be one more open view. v0.29 corrects the model and adds the tags Phase 1's layout needs. It changes nothing outside the editor and the server's file area.

## Layer 0 — Ontology

No change. EditorView stays the entity, joined by `pane_id`: the view shows the focused pane's session, and its records carry that pane.

## Layer 1 — Lexical

Five tags added.

- **EDITOR_DOCK_SET** (`dock`): the terminal docked bottom or right (spec §5.1 (2)).
- **EDITOR_SIDES_SWAPPED** (`swapped`): files and inspector swapped places (§5.1 (3)).
- **EDITOR_FOCUS_SET** (`on`): everything collapsed but the prompt, or the prior layout restored (§5.1 (4), frame 16c). Kept apart from EDITOR_COLUMN_FOLDED because focus is one command that folds up to three columns and later restores exactly the folds it changed; a reader of folds alone could not tell focus from three key presses.
- **EDITOR_COLUMN_RESIZED** (`column`, `size`): one record at a drag's end, never per pointer move.
- **DIFF_READ** (`session_id`, `base`, `files`), server: the per-session read the modified dots come from (D48: "modified-file dots come from the session's real worktree diff").

Considered and rejected: one EDITOR_LAYOUT_SET tag with a `setting` and a `value` field. Its `value` would be a string holding a bool for one setting and an enum for another, so no enum could type it (BOOTSTRAP step 3).

## Layer 2 — Payload

- VIEW_CHANGED: `from` and `to` take `editor`. The fields are typed as the open view's string, so the change is to the note and to `OpenView` in code.
- PANE_DRAWN.state loses `editor` (retired; see below).
- EDITOR_KEY_REFUSED.reason gains `no_session`.
- EDITOR_COLUMN_FOLDED gains required `cause`: `key | menu | rail | focus`.
- EDITOR_OPENED.binding and EDITOR_DRAWN.binding become optional. Phase 1 has no vim/nano setting; writing `vim` would invent a fact (D6). Phase 2, which adds the setting, makes them required again by proposal.
- EDITOR_DRAWN gains required `dock`, `sides_swapped`, `focus`, `tree_rows` and `modified_dots`.
- E1 holds: no field carries a path or text. `size` is a CSS pixel count.

## Layer 3 — Session

editor_run keeps its open (EDITOR_OPENED) and close (EDITOR_CLOSED, or PANE_CLOSED). Its persistent attribute `binding` is dropped with the field's move to optional. One editor_run is open at a time per window, under the focused pane.

## Layer 4 — Temporal

No change. The diff read has no window: git's time grows with the workspace.

## Layer 5 — State-Transition

No new rule. S10 and S11 (v0.28) have no code in the runtime checker, `electron/invariants.ts`, which implements S1–S9. S11 (EDITOR_OPENED first in an editor_run) gets its check in sprint 408, which follows sprint 407, the first to emit EDITOR_OPENED; S10 waits for Phase 3, which emits the follow chain.

## Layer 6 — Operator

EditorController emits the four new editor tags; Server emits DIFF_READ.

## Layer 7 — Evidence

No new constraint. E9 covers `no_session` as it covers the other reasons.

## Retirement: PANE_DRAWN.state=editor

Added in v0.28 (P-0.28-PANE-DRAWN-EDITOR) and emitted only by the build sprints 389–402 made, now set aside in `_deprecated/editor-phase-1-2026-11-09/`. A trace from that build still reads; the generated `PaneDrawnState` no longer offers the value, so no new code can write it.

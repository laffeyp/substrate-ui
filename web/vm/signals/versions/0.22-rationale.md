# v0.22 rationale — the server's pairings, read the way the code writes them (sprint 376)

## The changes

**`P-0.22-S7-WINDOW-SIDE`** (`INVARIANT_PROPOSED`, Layer 5). v0.21's S7 paired each server SESSION_CREATED with exactly one window SESSION_OPEN_ACKED. The server opens sessions for any client: its `/api` routes include `mcp` and `agent`, and `harness/shakeout/page_signals.ts` opens one with a plain `fetch`. No window acks those. S7 now pairs each window ack with exactly one server creation of the same session, written before it: the server writes SESSION_CREATED before it answers.

**`P-0.22-S8-SESSION-COUNT`** (`INVARIANT_PROPOSED`, Layer 5). v0.21's S8 paired TURN_ACCEPTED with TURN_ACK on `session_id` and `turn_index`, but TURN_ACK carries only `session_id`, and other clients post turns no window acks. S8's server half now reads: a session's window acks never outnumber its server-accepted turns.

T2 (SERVER_BOUND, then the server's SERVER_STARTED within 15 s) stands. `server.py` prints its port before it writes SERVER_STARTED, so main's SERVER_BOUND can come first.

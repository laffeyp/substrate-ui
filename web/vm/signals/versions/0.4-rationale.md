# v0.4 rationale — reveal shell vocabulary

v0.4 retires five tags, corrects three notes and adds two tags. The other thirty-one of v0.3's tags carry over unchanged. v0.3 stays as written and locked.

## Retired: the `spec` tags

`SPEC_VALIDATE_REQUESTED`, `SPEC_VALIDATED`, `SPEC_BUILD_REQUESTED`, `SPEC_BUILD_REJECTED` and `SPEC_BUILT` fired around POSTs to `/api/validate` and `/api/build` from Studio's form. The server has neither route; the lens-audit roadmap deleted them with the Studio backend. Studio's page, its button and the controller's `validateSpec` and `buildSpec` were removed in sprints 242–244, so nothing emits these tags. Each is kept in the file, marked `retired: true` with no replacement (`TAG_DEPRECATION_PROPOSED`: the system no longer admits the event). The parity gate fails if code emits a retired tag. The `spec` category stays listed, since retired tags still name it.

## Corrected notes

The tag names, categories and payload fields are unchanged; only the notes now say what the code does.

- **SESSION_END_REQUESTED.** The note named the reasons "user_ended, parity_harness_done". The code sends `user_end` from the end-session confirm (`/exit`) and `user_close` from Close Pane (⌘W).
- **SESSIONS_LOADED.** The note named `/api/sessions`; `loadLiveSessions()` reads `/api/session`.
- **CHILD_RECORD_ATTACH_REQUESTED.** The note named `attachChildRecord(recordRoot)`; the method is `attachRecordRoot`.

## Added: the `assays` category

The assay page reads the server's assays (plan row B5): `/api/assays` lists one row per cells file in the bench results folder, and `/api/assay/<name>` returns one assay's arm matrix. An assay is neither a session record nor a run the session started, so the two tags get their own category.

- **ASSAYS_LOADED** (`assays`, summary; payload `count`). `loadAssays()` read the listing; `count` is its rows. The listing's counterpart to `WORKSPACES_LOADED` and `SESSIONS_LOADED`.
- **ASSAY_REPORT_LOADED** (`assays`, summary; payload `name`, `arms`). `loadAssayReport(name)` read one assay's report; `arms` is the number of arms it holds.

Both loads return what they read to the page that asked, as `loadSessionsByWorkspace` returns its pages; the assays are the machine's, not the pane's, so they are not kept in a pane's snapshot. Unlike `loadSessionsByWorkspace`, each is a read a person starts (opening the page, picking an assay), so each is signalled.

A failed read leaves `lastError` set, as the other loads do, and emits no tag.

Both are `NEW_TAG_PROPOSED` (`grammar/PRINCIPLES.md`), ratified on the grounds recorded on `BLACKBOARD.md` on 2026-11-05.

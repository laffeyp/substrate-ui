# v0.26 rationale — the workspace file API (sprint 387)

*Locked 2026-11-08. Supersedes `0.25.json`; 114 tags, 113 live. Earlier rationales cover everything not named here.*

## The change

**`P-0.26-WORKSPACE-FILES`** (Layer 1, five server tags). The workspace file API is the editor view's way to the session's files (editor plan round 2, item 0(c)). Sprints 348 and 349 built its list, read and watch before the trace rule, with no tags. Sprint 387 adds the write, and gives every call a tag:

- **FILES_LISTED**: the number of entries.
- **FILE_READ**: the file's size and its encoding (`utf8`, `binary` or `too_large`).
- **FILE_WRITTEN**: the bytes written, whether the file was created, `at_rest` or `live`, and the kernel `seq` of the FileWritten entry. The seq joins the trace to the record.
- **FILES_WATCH_OPENED and FILES_WATCH_CLOSED.**

Paths and text stay out of every tag (E1); the kernel record holds them. A refused call stays an API_REFUSED with area `files`.

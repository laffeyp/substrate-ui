# v0.8 rationale — SERVER_STARTED split from the store scan (sprint 354)

*Locked 2026-11-06. Supersedes `0.7.json` (87 tags); `0.8.json` has 88. Everything not named here carries over from v0.7 unchanged; `0.7-rationale.md` remains the rationale for those layers.*

## The change

One proposal, `P-0.8-SPLIT-SERVER_STARTED` (`TAG_SPLIT_PROPOSED`, `../proposals.json`).

In v0.7, `SERVER_STARTED` carried the port and the boot scan's counts, and `server.py` wrote it when the scan ended. The scan runs on a background thread after both listeners serve (F319): on a store of about 4,000 sessions it takes 5–15 s, and requests are answered during it. So one tag named two events seconds apart. Three locked rules read it as the first event:

- S1: `SERVER_STARTED` is the server's first record.
- The `server_run` session opens on `SERVER_STARTED` and frames every server record.
- T2: `SERVER_BOUND` to `SERVER_STARTED` within 15,000 ms, sourced from main's `HEALTH_TIMEOUT_MS`, which waits for the server to answer, not for the scan.

Once a request record exists (plan item 4), a correct run breaks all three. Sprint 353 recorded the clash as `P-0.7-OPEN-S1-SERVER`, which proposed restating S1 to allow request records before `SERVER_STARTED`. That would have left `server_run` without a correct open tag and T2 measuring the wrong interval. The split fixes the cause instead:

| Tag | Payload | Written |
|---|---|---|
| `SERVER_STARTED` (event) | `port` | after the port readback, before either listener serves |
| `STORE_SCANNED` (summary, new) | `sessions_found`, `parked`, `interrupted`, `ended`, `skipped`, `duration_ms` | when the boot scan ends |

`skipped` (manifests that did not parse) and `duration_ms` were already in the scan's stdout line; they move into the record. With the split, S1, `server_run` and T2 hold as their sources mean them. S1's statement now also says when the tag is written. `P-0.7-OPEN-S1-SERVER` is withdrawn, pointing at the split.

- No silent change: the v0.7 tag's payload change is the split proposal; no other tag, rule or session changes.
- Payload rule (E1): counts and a duration only.

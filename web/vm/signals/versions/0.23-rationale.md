# v0.23 rationale — pane 1 opens where it is created (sprint 377)

*Locked 2026-11-08. Supersedes `0.22.json`; 88 tags, 87 live. Earlier rationales cover everything not named here.*

## The change

**`P-0.23-PANE-ONE-OPENED`** (Layer 6, the emit site). `web/reveal.ts` creates pane 1's controller and, on a reload with `?session=`, attaches its session before the App mounts. The App's mount wrote pane 1's PANE_OPENED, so the trace held pane 1's SESSION_ATTACH_STARTED before pane 1 was opened, outside its pane's frame (Layer 3). The runtime checker's first run of all gates showed it (`graph_model_lane_on_resume`, `resume_after_two_ends`). PANE_OPENED for pane 1 is now written in `web/reveal.ts` right after the spawn; the App's mount writes it for every other starting pane. The tag, its payload and its meaning are unchanged.

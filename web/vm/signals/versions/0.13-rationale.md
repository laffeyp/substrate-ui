# v0.13 rationale — where a transcript sits (sprint 359)

*Locked 2026-11-07. Supersedes `0.12.json`; still 88 tags. Plan `process/planning/2026-11-05-sdd-signals/`, item 4, the transcript scroll. Earlier rationales cover everything not named here.*

## The changes

Three proposals in `../proposals.json`, each read off `web/reveal/transcript/useScrollAnchor.ts`, the one owner of a pane's transcript scroll.

**`P-0.13-SCROLL-CAUSE`** (`PAYLOAD_FIELD_PROPOSED`). `TRANSCRIPT_SCROLLED.cause` gains `resized`. The hook moves the view on four occasions, not three: a React commit of the rows (`row_arrived`), the user's scroll (`user`), a ResizeObserver firing when content grows outside a commit or the scroller changes size (`resized`), and the transcript shown again (`view_switch`). Writing the third as `row_arrived` would say a record entry arrived when none did.

**`P-0.13-SCROLL-PINNED`** (`PAYLOAD_FIELD_PROPOSED`). A required `pinned` field. A click on a card header holds that header at its offset, in either mode, until the user scrolls (sprint 075's caret pin). While it holds, a following transcript is not at the bottom, by design. Without the field a reader cannot tell that from the 2026-10-02 regression, a transcript that followed and was not at the bottom.

**`P-0.13-E8-FOLLOW`** (`INVARIANT_PROPOSED`). Evidence rule E8: in `TRANSCRIPT_SCROLLED`, following and not pinned implies at_bottom. `harness/shakeout/transcript_follow.ts` reads it from every record; plan item 5's runtime checker will too.

## When a record is written

For `view_switch`, each time the pane's transcript is shown again: the record is the place restored. For the other three causes, only when `at_bottom`, `following` or `pinned` differs from the last record for that pane and view. A wheel scroll fires a scroll event per frame and a streamed reply a commit per chunk, and the place changes at a few of them. The first draw of a pane's transcript writes nothing; it starts following, at the bottom.

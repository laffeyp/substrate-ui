# v0.68 rationale — the boot record names its install

*2026-11-11, sprint 490. Bumps v0.67 to v0.68 (157 tags). One proposal: P-0.68-APP-NAME. Grounds: the second build (roadmap `2026-11-11-second-build` r1 E4): the working install (Substrate) and the test install (Substrate Next) run on one machine, and their `APP_BOOTED` records agreed on every field but the version fields.*

## Layer 2 — Payload

`APP_BOOTED` gains `app_name` (string): the name the app runs under, which `electron/main.ts` sets from its install's identity record (`electron/identity.json`) before any path lookup, so it is also the name of the app's data folder and log folder. Values today: `Substrate`, `Substrate Next`, and `Substrate Dev` for a launch with `SUBSTRATE_HOME` set (a gate, `npm run electron`). A string, not an enum: the identity record, not the vocabulary, lists the installs.

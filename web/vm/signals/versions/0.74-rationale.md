# Vocabulary 0.74 — P-0.74-WINDOW-FAULTED-AREA

Sprint 527. Supersedes 0.73.

## Proposal

**P-0.74-WINDOW-FAULTED-AREA** (payload field proposed): add `area` as an optional string field to `WINDOW_FAULTED`.

React error boundaries catch render errors inside a named area of the window (transcript, meta, editor, records, assays, studio) and emit `WINDOW_FAULTED` with the area that faulted. Uncaught exceptions and rejections that reach the global handler continue to omit the field, so existing emitters are unchanged.

## Grounds

- **Project.** WINDOW_FAULTED's current payload (`error_type`, `source`, `where`) tells what failed and how, but not which part of the window broke. Error boundaries partition the render tree; the trace needs to name which partition caught the error.
- **SDD practice.** Hard rule 2: vocabulary is the contract; a payload shape change is proposed, ratified, version-bumped, and recorded.
- **Engineering practice.** React error boundaries are class components that catch errors in the render tree below them; `componentDidCatch` receives the error and an info object naming the component stack. The boundary emits the signal; the area name comes from the boundary's props.

## Decision

Ratified. The field is optional: existing global-handler emitters pass no area and remain valid.

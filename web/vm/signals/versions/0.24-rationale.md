*Locked 2026-11-08. Supersedes `0.23.json`; 109 tags, 108 live. Earlier rationales cover everything not named here. Plan `process/planning/2026-11-05-sdd-signals/PLAN-2026-11-08-sdd-signals-r4.md`, items 9–11.*

## The changes

**`P-0.24-FAULTS`** (Layer 1, eight tags). A crash or a hang wrote nothing: the window had no `error` or `unhandledrejection` listener, main no `render-process-gone`, `unresponsive` or uncaught-exception handler, and `server.py` `_run_background` printed its exception to stderr only. Now:

| Tag | Process | Emitted from |
|---|---|---|
| WINDOW_FAULTED (error, rejection, preload) | window; preload from main | `web/reveal.ts`; `electron/main.ts` `preload-error` |
| MAIN_FAULTED (exception, rejection) | main | Node's `uncaughtExceptionMonitor` and `warning` events |
| RENDERER_GONE | main | `render-process-gone` |
| WINDOW_UNRESPONSIVE, WINDOW_RESPONSIVE | main | `unresponsive`, `responsive` |
| CHILD_PROCESS_GONE | main | `child-process-gone` |
| RUN_FAULTED | server | `_run_background` |
| SERVER_UNCAUGHT | server | `threading.excepthook`, `sys.excepthook`, chained to the hooks before |

Every hook observes. Measured on Electron 44 (2026-11-08): an unhandled rejection in main is a printed warning and the app goes on, so it is read from the `warning` event, which leaves the warning printed; an uncaught exception in main shows Electron's error box, which `uncaughtExceptionMonitor` precedes and does not stop. `unresponsive` repeats about every 16 s during one hang, so one WINDOW_UNRESPONSIVE is written per hang. React 18 rethrows a render error that no boundary catches; it reaches the window's `error` event (planted in `fault_signals.ts`). No payload carries message text (E1): the error's class, the script file and line, the server function.

**`P-0.24-SERVER-EXITED-CAUSE`** (Layer 7). SERVER_EXITED gains optional `error_type`, the exception class on the last line of the server's stderr. Launch `20261108-060110-406b03` ended at SERVER_EXITED code 1 with its cause, a missing `signals_gen.py`, only in `substrate.log`.

**`P-0.24-ACTIONS`** (Layer 1, thirteen tags). STREAM_DIRECTION_SET, STREAM_LEVEL_SET, SEQ_SELECTED, LANGUAGE_STREAM_SET, LANGUAGE_VIEW_SET, LANGUAGE_LANE_SET, FIND_OPENED, FIND_CLOSED, FIND_QUERY_CHANGED (the query's length), FIND_SCOPE_SET, TOP_BAR_CARD_SET, TOOL_CARD_TOGGLED, TOOL_OUTPUT_MODE_SET. Each is written when its value changes, except TOOL_OUTPUT_MODE_SET, which is written each time it is applied, since a second `/unfold` reopens the cards a click closed. A tool card that the fold toggle opens writes no TOOL_CARD_TOGGLED: only a click makes the element differ from its state.

**`P-0.24-S2-NEXT-BOOT`** (Layer 5). S2, APP_QUIT_COMPLETED as main's last record, was checked nowhere. Main's writer refuses records after it, so S2 breaks only when a boot ends without it, which that boot cannot report. One app runs per machine, so the next boot in the same trace folder reads the last boot's main.jsonl and writes INVARIANT_BROKEN S2 naming that boot and its last record.

**`P-0.24-S1-SERVER-CRASH`** (Layer 5). A server that dies before it binds writes the SERVER_UNCAUGHT it dies of as its first and only record; S1 admits it.

**`P-0.24-T1-T2-END-AT-EXIT`** (Layer 4). A server that exits ends the T1 and T2 waits on its start: its SERVER_EXITED is the incident, and a T1 five seconds later would report the same fault twice.

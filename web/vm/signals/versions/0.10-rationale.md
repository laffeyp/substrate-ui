# v0.10 rationale — what main can know about a quit and a new window (sprint 356)

*Locked 2026-11-06. Supersedes `0.9.json`; still 88 tags. Plan `process/planning/2026-11-05-sdd-signals/`, item 4, the first area: Electron main. Earlier rationales cover everything not named here.*

## The changes

**`P-0.10-QUIT-CAUSE`** (`PAYLOAD_FIELD_PROPOSED`). `APP_QUIT_REQUESTED.cause` was `menu | last_window | signal | update`. Writing its emit site showed three of the four values cannot be known or cannot happen:
- Electron's `before-quit` does not say who asked, so Cmd-Q from the app menu's quit role, the Dock, logout and a test driver look the same.
- Nothing in the app updates itself or traps a process signal.

Main starts two quits itself and neither had a value: the backend failing at startup, and the backend dying while the app runs. The latter goes through `app.exit`, which skips `before-quit`. The values are now:
- `app`: any quit asked from outside main's code;
- `last_window`;
- `startup_failed`;
- `backend_died`.

**`P-0.10-WINDOW-CAUSE`** (`PAYLOAD_FIELD_PROPOSED`). `WINDOW_OPENED.cause` loses `second_instance` and `deep_link`. Both paths focus the current window, and no code opens one for them.

## Found while emitting

The backend-death path ends with `app.exit`, which skips `will-quit`, so `APP_QUIT_COMPLETED` (S2, the launch's last record) was never written there. `electron/main.js` now writes it in that path through `closeTrace()`. It closes the windows first, so each `WINDOW_CLOSED` precedes it; a window's close had been lost after the closing record, and the closing record still reported nothing lost. A record that arrives after the trace is closed is now said on stderr.

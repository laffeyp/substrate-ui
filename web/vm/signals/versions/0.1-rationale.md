# v0.1 rationale — reveal shell vocabulary

## Intent and scope

The reveal shell is a separate SDD system from the classic shell. The
classic shell has its own vocabulary at `signals/versions/0.7.3.json`,
its own emitter at `web/instrumentation/sdd.ts`, and its own parity
gate at `tools/check-vocabulary-parity.ts`. Nothing here imports
anything there.

v0.1 covers the `SessionController` in `web/vm/session_controller.ts`
— the presentation model that both the reveal shell (`/`) and the
classic shell's phase-2a boot (`/classic`) construct at boot. The
controller's every `this.emit(tag, ...)` call site fires exactly one
tag. This lock names all thirty of them.

The reveal shell's `web/reveal.ts` currently emits nothing itself; it
subscribes to the controller and mirrors snapshots into the DC
component. When the reveal shell grows its own emit sites (view
toggles, pane switches, inspector opens), they land as v0.2.

## Layer 0 — entities

- **Session.** A driver-session in substrate: one LLM plus its
  tool loop plus its conversation, kept alive across many turns.
  Identified by `session_id`.
- **Driver.** The model name selected for a session (kimi-k2.7-code,
  llama3.2:1b, deterministic).
- **Bundle.** A published topology template the user can launch a
  session against. Identified by slug.
- **Workspace.** A directory the session's tools operate against.
- **Turn.** One user prompt plus the driver's reply and tool calls
  that follow before the next user prompt. Indexed within a session
  from zero.
- **Envelope.** One typed record in substrate's Run: `UserMessage`,
  `ModelReply`, `ToolCall`, `ToolResult`, `Park`, `SessionEnded`, etc.
  Identified by `seq` within a Run.
- **Record.** A substrate Run persisted on disk (`~/.substrate/runs/<name>`
  or `~/.substrate/sessions/<id>/record`).
- **ChildRecord.** A substrate Run started by a tool call (delegate),
  addressable by its record_root.
- **Stream.** The SSE connection between the browser and the server
  that carries envelopes.
- **Spec.** An authored topology description passed to `/api/validate`
  and `/api/build`.
- **Topology.** The graph of Producers, Triggers, Routes, and Views
  in a Run.

## Layer 1 — tags (thirty)

Grouped by category, listed in the lock file:

- session: `SESSION_OPEN_REQUESTED`, `SESSION_OPEN_ACKED`,
  `SESSION_OPEN_REFUSED`, `SESSION_ATTACH_STARTED`,
  `SESSION_END_REQUESTED`, `SESSION_ENDED_LOCAL`
- driver: `DRIVER_ROSTER_LOADED`, `DRIVER_PICKED`
- bundle: `BUNDLE_ROSTER_LOADED`, `BUNDLE_PICKED`
- workspace: `WORKSPACES_LOADED`
- turn: `TURN_SUBMITTED`, `TURN_ACK`, `TURN_REFUSED`, `TURN_PARKED`,
  `TURN_INTERRUPTED`
- stream: `STREAM_ATTACHED`, `STREAM_CLOSED`, `STREAM_RECONNECTING`,
  `STREAM_ENVELOPE_APPENDED`
- records: `SESSIONS_LOADED`, `CHILD_RECORD_ATTACH_REQUESTED`
- topology: `TOPOLOGY_LOADED`
- spec: `SPEC_VALIDATE_REQUESTED`, `SPEC_VALIDATED`,
  `SPEC_BUILD_REQUESTED`, `SPEC_BUILD_REJECTED`, `SPEC_BUILT`
- slash: `SLASH_ROUTED`, `SLASH_UNKNOWN`

Names carried from the classic vocabulary where the meaning matches
(SPEC_*, WORKSPACES_LOADED). Names distinct where the controller
seam is new (SESSION_OPEN_*, STREAM_*, SLASH_*, TURN_ACK). The
reveal shell does not inherit classic's per-pane render tags
(`GRAPH_RENDERED`, `IO_RENDERED`, `STREAM_RENDERED`, `PANE_SWITCHED`,
`VIEW_SWITCHED`, etc.) — the DC template renders differently and
those tags would not mean the same thing here.

## Layer 2 — payloads

Read off the emit call sites in
`web/vm/session_controller.ts`. `STREAM_ATTACHED`, `STREAM_CLOSED`,
and `STREAM_RECONNECTING` each have two call sites: one for a session
stream (payload `session_id`), one for a child-record stream (payload
`record_root`). Both fields are optional in the lock; exactly one is
present at each call. This mirrors the branching in the controller
without splitting the tag.

## Layer 3 — sessions

The reveal shell's browser tab is the outer session (implicit, no
`SESSION_INIT` tag at the controller level — the classic tags
`SESSION_INIT` / `SESSION_ENDED` are browser tab open/close, distinct
concern, and live in classic's lock). The controller's own sessions
are the substrate driver-sessions above.

## Layer 4 — temporal invariants

Deferred to v0.2. The obvious ones — `SESSION_OPEN_REQUESTED` precedes
`SESSION_OPEN_ACKED` or `SESSION_OPEN_REFUSED` for the same session;
`TURN_SUBMITTED` precedes `TURN_ACK` or `TURN_REFUSED`;
`STREAM_ATTACHED` precedes `STREAM_ENVELOPE_APPENDED` on the same
stream — will get named and checked in the harness once v0.1 has run
long enough to reveal which invariants are actually stable.

## Layer 5 — state transitions

Deferred to v0.2 alongside temporal invariants.

## Layer 6 — operators

The `SessionController` itself is the operator. Its collaborators
are typed ports: `SubstrateClient` (transport), `PaneRegistry` (fan
per-pane events).

## Layer 7 — evidence

Deferred to v0.2.

## Layer 8 — report

The parity harness `web/vm/tools/check-vocabulary-parity.ts` grades
by comparing `window.__vmSignals` (validated buffer) and
`window.__vmTape` (per-pane ring buffer) against this lock.

## Layer 9 — version

v0.1. First lock of the reveal shell's own vocabulary. Prior classic
locks (0.1 through 0.7.3) live under `signals/versions/`; they are
the classic shell's history and are not superseded by this file.

## Layer 10 — grammar growth

Standard proposal taxonomy per `sdd-kit-2/grammar/PRINCIPLES.md`.

## Open proposals for v0.2

- Add reveal-shell view/pane tags once `web/reveal.ts` grows its own
  emit sites.
- Name the temporal invariants for the pair chains above and enforce
  in the parity harness.
- Split `STREAM_ATTACHED` and friends into session-scoped and
  record-scoped variants if the optional-field branching gets in the
  way of grading.

# v0.7 rationale — the whole-app vocabulary (draft; sprint 350)

*Draft until Step 12. Plan: `process/planning/2026-11-05-sdd-signals/PLAN-2026-11-05-sdd-signals-r3.md`, item 1. Step 0: `process/planning/2026-11-05-sdd-signals/RESEARCH-2026-11-05-vocabulary-inventory.md`.*

## Intent and scope

v0.7 is the vocabulary of substrate-ui as a whole running program: the window, Electron main and the server, joined to the kernel's run records. It starts from v0.6's 42 locked tags; every change to them is a typed proposal in `../proposals.json`.

## Layer 0 — Ontology (Step 1)

Twenty-five entities in `0.7.json` under `ontology`, each with a definition, a source in the code and a home. Sixteen are the app's own: AppBoot, Window, Server, Pane, Picker, OpenView, Page, Lens, Dialog, KeyAction, Stream, Transcript, Spec, Assay, CliLogin, TraceFile. Nine are the kernel's (Workspace, Driver, Session, Turn, RecordEntry, Run, Task, Child, Record): each is an `ENTITY_MERGE_PROPOSED`, ratified, naming the kernel as home and the key app tags carry to join it (`session_id`, `turn_index`, `seq`, `run_id`, the workspace path, the driver name, the record path). The app redeclares none of their kinds.

Considered and left out: Request (an HTTP call is a transport, not a domain entity; foundation 02, "signal is not log"); Snapshot and row types (value objects of the controller); the gates and packaging (tooling, not the running program).

### A finding from the join

The kernel's session vocabulary, § G, pairs each session kind with a substrate-ui tag that proves it was drawn: `UserMessage` with `USER_MESSAGE_INJECTED`, `ModelReply` with `PANE_SCROLLED{model_reply_ref}`, `SessionStarted` with `DRIVER_SESSION_STARTED`, and five more. Those tags were in `substrate-ui/signals/versions/0.6.json`, the classic shell's vocabulary, retired with that shell on 2026-09-22. The current window vocabulary (`web/vm/signals/versions/`) has none of them, so since then nothing records that a record event reached the screen. Step 9's audit restores the pairing for every session kind the window shows. The label "substrate-ui v0.6" names two different files; this vocabulary's versions are cited by path from here on.

### Self-review

- Under-extraction: each surface in `WORKING_AGREEMENT.md`'s canonical-home registry maps to an entity above or is recorded as tooling. The registry itself is stale (it names the retired dc-runtime layout and has no row for `web/app/`); it is corrected before plan item 2 writes code.
- Over-extraction: every entity has a source and holds state.
- Polysemy: the nine kernel entities each have a recorded merge decision.

## Layer 1 — Lexical (Step 2)

v0.6's 42 tags carry over unchanged. Some do not follow the `ENTITY_VERB_PAST` form (`TURN_ACK`, `TURN_REFUSED_VIEW_ONLY`); renaming a locked tag is a `TAG_SPLIT_PROPOSED` or `TAG_DEPRECATION_PROPOSED` with a deprecation entry and a churn of every reader, for no gain in meaning, so they stay as they are.

Forty-two new tags, each a `NEW_TAG_PROPOSED` in `../proposals.json` with its emit site (84 tags in all, 20 categories). They follow the design spec's rule (§0) that "each tool event moves the view, live", which needs view tags, and the kit's rule that a mock, fallback or failure path can say it is one:

- **app** (Electron main): the launch (`APP_BOOTED`, `APP_QUIT_REQUESTED`, `APP_QUIT_COMPLETED`), the server process (`SERVER_SPAWNED`, `SERVER_BOUND`, `SERVER_EXITED`), windows (`WINDOW_OPENED`, `WINDOW_CLOSED`, `NAVIGATION_BLOCKED`), the OS and menus (`DEEP_LINK_RECEIVED`, `MENU_COMMAND_SENT`, `NATIVE_DIALOG_CLOSED`).
- **window**: `WINDOW_BOOTED`, `VIEW_CHANGED` (panes, meta and every page), `KEY_ROUTED` (named keys only, never typed characters), `DIALOG_OPENED`, `DIALOG_CLOSED`.
- **pane**: `PANE_OPENED`, `PANE_CLOSED`, `PANE_FOCUSED`, `PANE_BOUND`, `LENS_CHANGED`.
- **transcript** (the view side of the kernel record): `TRANSCRIPT_ROW_DRAWN` with the entry's `seq` and kind, and `TRANSCRIPT_ROW_SKIPPED` with the reason. These restore the pairing the kernel's session vocabulary § G names.
- **controller gaps**: `WORKSPACE_ADDED`, `CONTROLS_PICKED`, `SESSION_RENAMED`, `TASK_STOP_REQUESTED`, `RECORD_OPENED`.
- **cli**: `CLI_STATUS_CHECKED`, `CLI_LOGIN_PROMPTED`, `CLI_LOGIN_FINISHED`.
- **server** (domain events, not HTTP lines): `SERVER_STARTED`, `SESSION_CREATED`, `TURN_ACCEPTED`, `API_REFUSED` (every error response, by area and cause), `SERVER_FAULTED`, `SERVER_STOPPED`.
- **trace**: `TRACE_OPENED`, `TRACE_LOST`, `SIGNAL_REJECTED`, `INVARIANT_BROKEN`.

Folded, not tagged one by one: the ~115 window input handlers become the domain events above (a pick, an open, a close, a view change), not one tag per button (foundation 01: tags name what happened).

- Strata: incidents only where something needs attention (`SERVER_EXITED` unexpected, `NAVIGATION_BLOCKED`, `API_REFUSED`, `SERVER_FAULTED`, `TRACE_LOST`, `SIGNAL_REJECTED`, `INVARIANT_BROKEN`); summaries at boundary close (`APP_QUIT_COMPLETED`, `SERVER_STARTED`, `SERVER_STOPPED`).
- Payloads are listed; Step 3 types each field and fixes its enum values.

## Layer 2 — Payload (Step 3)

Every field of the 84 tags is typed in its tag's `field_types`; every enum lists its values. Fields that join to the kernel carry the kernel's keys (`session_id`, `seq`, `turn_index`, `run_id`).

**Record context** (`PAYLOAD_FIELD_PROPOSED` P-0.7-CONTEXT). No v0.6 window tag says which pane or window it belongs to: with two panes open, `SESSION_OPEN_REQUESTED`, `TURN_SUBMITTED` and the stream tags cannot be told apart, and records from three processes cannot be put in order. The emitter stamps six fields on every trace record, outside the payload: `boot_id`, `process` (main, window, server), `proc_seq` (the order key), `wall` (recorded, never used to order), `window_id`, and `pane_id` when the emitting code belongs to one pane. The 42 carried-over tags gain the join with no rename; the new tags carry no `boot_id` or `window_id` field of their own.

**Validator extras: strict.** A payload field not declared on its tag is a `SIGNAL_REJECTED` (problem `extra_field`), as an undeclared tag is. The per-build posture (raise in source and test builds, emit the incident in the packaged app) is the plan's item 1 rule; Step 8 binds it as evidence.

**Semantic boundaries.** `KEY_ROUTED.key` is a named key with modifiers (`Enter`, `Escape`, `Meta+d`), never a printable character. `SERVER_STARTED` counts manifests as `sessions_found`; `sessions` stays the list of run sessions on `RUN_STARTED`, its v0.6 meaning. `API_REFUSED.cause` is a short code, not the request's content. `workspace` and `record_root` are paths, the join keys to the kernel's Workspace and Record; Step 8 decides what else a path may carry.

### Self-review

- No field is untyped; no enum lacks its values.
- Every `_id` field resolves to a Layer-0 entity: `pane_id` (Pane), `window_id` (Window), `session_id` (Session), `run_id` (Run), `task_id` (Task), `boot_id` (AppBoot); `seq` and `turn_index` to RecordEntry and Turn.
- Validator posture recorded: strict.

## Layer 3 — Sessions (Step 4)

Six nested streams in `sessions`: `app_boot` (`APP_BOOTED` … `APP_QUIT_COMPLETED`) holds `server_run` (`SERVER_STARTED` … `SERVER_STOPPED`) and `window` (`WINDOW_BOOTED`, closed by main's `WINDOW_CLOSED`); a window holds `pane` (`PANE_OPENED` … `PANE_CLOSED`); a pane holds `picker_run` (open while unbound, re-entered on `PICKER_FOLDER_DISARMED`, closed by `PICKER_COMMITTED`) and `pane_session` (`SESSION_OPEN_ACKED` or `SESSION_ATTACH_STARTED` … `SESSION_ENDED_LOCAL`), which joins the kernel Session. Persistent attributes sit on the open tag and in the record context, nowhere else.

## Layer 4 — Temporal (Step 5)

Six invariants, each duration from the code or a named source: T1–T3 from `electron/main.js` (`READBACK_TIMEOUT_MS` 5 s, `HEALTH_TIMEOUT_MS` 15 s, `KILL_GRACE_MS` 45 s); T4, a record entry the pane received is drawn or skipped with its reason within 1 s (Nielsen 1993: the limit for the flow of thought), which is the screen-equals-record rule; T5 and T6, a session open and a turn are answered within 10 s (Nielsen 1993: the limit for attention). No tag is ambient, so no cadence is needed.

## Layer 5 — State transitions (Step 6)

Nine rules: S1–S2 first and last records; S3–S4 the picker's order; S5 one session per pane at a time; S6 open before ack; S7–S9 across processes (each server `SESSION_CREATED`, `TURN_ACCEPTED` and `API_REFUSED` pairs with its window tag in the same boot). The cross-process rules are why the record context carries `boot_id` and the payloads carry `session_id`.

### Self-review (Steps 4–6)

- Every session has an open tag, a close tag or a stated inference, and its frames; nesting is explicit.
- Every duration is a number with a unit and a source.
- The picker's re-entry is a named loop (S3), not a cycle by accident. Each session's close tag ends it (S2 for the boot).

## Layer 6 — Operators (Step 7)

Six operators, each with its home in the code and the tags it emits, mapped by each tag's `emit_site` so a tag leads to its code: AppMain (`electron/`), WindowShell (`web/app/App.tsx`, `keymap.ts`, `Dialogs.tsx`, `web/reveal.ts`), PaneController (`web/vm/session_controller.ts`, one per pane), TranscriptRenderer (`web/reveal/transcript/`), Server (`server.py`'s `Handler` and `_daemon_driver_resolver`), Sink (the trace writers, plan item 2). Every tag has exactly one operator. Runtime grammar: which route a driver takes (a CLI agent, an Ollama model, deterministic) is named by `SESSION_CREATED.driver` and the kernel's `SessionStarted`; a fallback the server takes is an `API_REFUSED` or a `SERVER_FAULTED`, never silent. Pane and Server are both entities and operators.

## Layer 7 — Evidence (Step 8)

Seven constraints (`evidence_constraints`): E1 no content in any payload (no message, model output, file, prompt, environment or credential text; content stays in the kernel record, reached by `session_id` and `seq`); E2 string reasons at most 200 characters; E3 each incident carries its diagnostic fields; E4 each summary its outcome; E5 numeric ranges; E6 the per-build posture (raise in source and tests, `SIGNAL_REJECTED` in the packaged app, the request goes on); E7 `session_id` and `seq` resolve in the boot's store. All are mechanical.

### Self-review (Steps 7–8)

- Operator boundaries follow the code's modules; no tag lacks an operator; no operator lacks tags.
- Every incident tag has a diagnostic constraint (E3); enforceability is mechanical throughout.

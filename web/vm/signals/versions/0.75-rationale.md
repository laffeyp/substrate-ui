# Vocabulary 0.75 — P-0.75-RENDERER-RECOVERY

Sprint 528. Supersedes 0.74.

## Proposal

**P-0.75-RENDERER-RECOVERY** (new tags proposed): add `RENDERER_RECOVERY_OFFERED`, `RENDERER_RECOVERY_CHOSEN` and `WINDOW_REOPENED` to the `app` category.

When a window's renderer dies (`render-process-gone`, already recorded as `RENDERER_GONE`), main now shows a recovery dialog and records the flow: the dialog shown (RENDERER_RECOVERY_OFFERED), the action the user picked (RENDERER_RECOVERY_CHOSEN), and the reload that follows a reopen (WINDOW_REOPENED). A rapid re-crash within 60 seconds of the last reopen shows a different dialog (RENDERER_RECOVERY_OFFERED with `rapid: true`) that offers an empty reopen, so a crashy session does not loop.

## Tags

- **RENDERER_RECOVERY_OFFERED** (event, app). Payload: `reason` (echoed from RENDERER_GONE), `exit_code`, `rapid` (bool: true when the crash hit the 60 s rapid-crash guard). Emit site: `electron/main.ts render-process-gone`.
- **RENDERER_RECOVERY_CHOSEN** (event, app). Payload: `action` (enum `reopen | reopen_empty | close`). Emit site: `electron/main.ts render-process-gone`.
- **WINDOW_REOPENED** (event, app). No payload. Emit site: `electron/main.ts render-process-gone recovery` (the did-finish-load after a recovery reload).

## Grounds

- **Project.** RENDERER_GONE recorded the death but not the recovery: a trace that shows the crash and not what followed is incomplete. The recovery dialog is a main-process action invisible to the window, so only main can record it.
- **SDD practice.** Hard rule 2: vocabulary is the contract; a new tag is proposed, ratified, version-bumped, and recorded.
- **Engineering practice.** VS Code's `windowImpl.ts` pattern: a dialog with the reason and exit code, two buttons. Electron PR #51900 requires deferring the reload out of the event handler. The 60 s rapid-crash guard prevents an infinite crash-reopen loop.

## Decision

Ratified. Three new tags in the `app` category, all emitted by `electron/main.ts`.

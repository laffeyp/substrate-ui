# v0.12 rationale — transcript rows drawn and skipped (sprint 358)

*Locked 2026-11-06. Supersedes `0.11.json`; still 88 tags. Plan `process/planning/2026-11-05-sdd-signals/`, item 4, the transcript area. Earlier rationales cover everything not named here.*

## The changes

**`P-0.12-ROW-SESSION`.** `TRANSCRIPT_ROW_DRAWN.session_id` and `TRANSCRIPT_ROW_SKIPPED.session_id` admit null. A pane showing an attached record streams it with no session id, and T4 asks for every received entry to be drawn or skipped there too.

**`P-0.12-SKIP-REASONS`.** The four skip reasons are defined against the code that decides them:
- `hidden_kind`: the controller's `KIND_DISPOSITION` marks the kind `ignored`. That table classes every kernel kind, and the compiler enforces it.
- `folded`: the entry is drawn inside another row. A tool result goes in its call's card (`Transcript.tsx`); tool progress goes there too (the controller).
- `duplicate_seq`: the stream replayed an entry the controller already holds.
- `other`: a kind the controller renders made no row this time. Examples: an empty reply, a final answer that repeats the reply, `SessionStarted` shown in the header, a `RunFinalised` with no orphaned call.

## Where each is written

`TRANSCRIPT_ROW_DRAWN` is written in `Row.tsx`'s mount effect, after React commits the row. A row the window made itself (the local echo, a note, help, a model-error line) has a negative or fractional seq, so it is written with seq null and kind `local:<kind>`. A local echo replaced by its record entry mounts again under the record's seq and is drawn a second time with it.

# v0.15 rationale — what a pane draws (sprint 362)

*Locked 2026-11-07. Supersedes `0.14.json`; still 88 tags. Plan `process/planning/2026-11-05-sdd-signals/`, item 4, `PANE_DRAWN`. Earlier rationales cover everything not named here.*

## The changes

Three proposals in `../proposals.json`.

**`P-0.15-DRAWN-CONNECTION`** (`PAYLOAD_FIELD_PROPOSED`). `PANE_DRAWN.connection` gains `idle`. `web/vm/types.ts` `ConnectionState` has five states, and a bound pane whose session has not opened yet is `idle`. Under v0.7's four values, every record of such a pane would have been rejected.

**`P-0.15-DRAWN-TURN`** (`PAYLOAD_FIELD_PROPOSED`). `turn_state` is what the activity line draws (`web/reveal/activity.ts` `liveActivity`):

| Value | The strip shows |
|---|---|
| `idle` | nothing; no turn yet |
| `running` | a live turn, pulsing |
| `failed` | the last turn's request failed, in red; new |
| `parked` | the last turn returned or parked |
| `ended` | the session ended (the snapshot's `endedReason`) |

**`P-0.15-DRAWN-FIELDS`** (`INVARIANT_PROPOSED`). Each state carries the same optional fields:
- `picker`: `picker_line`, `armed`, `folder_rows`, `model_rows`, `driver_shown`;
- `session` and `record`: `connection`, `turn_state`, `driver_shown`, `named`, and `session_id` when the pane holds one.

A record is written only when one of these differs from the pane's last record.

## Where it is written

`App.tsx` `notePaneDrawn`, after `publish` in `componentDidMount` and `componentDidUpdate`. Its values are the ones `publish` just gave the areas that draw the pane: the picker's view, or the session's snapshot. Those areas (`PanePicker`, `PaneSession`) draw them from their stores in the render that follows.

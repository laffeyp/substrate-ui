# v0.28 rationale — the code editor

*2026-11-09. Bumps v0.27 (114 tags, 20 categories) to v0.28 (130 tags, 21 categories). Three proposals: P-0.28-EDITOR (16 new tags), P-0.28-PANE-DRAWN-EDITOR (PANE_DRAWN.state gains `editor`), P-0.28-KEY-ROUTED-EDITOR (KEY_ROUTED.target gains `editor`).*

---

## Intent and scope

The code editor view (⌘⇧E) is the first mode beyond terminal and meta. It opens a file tree, a tab row, CodeMirror instances, an inspector spine, and three foldable columns inside a pane. The vocabulary needed tags for the interactions the roadmap names: file opened, column folded, follow mark, hunk drawn, chip added, search, quick open, key refused. The E1 rule applies to every new tag: no path or text in the trace. A file is identified by following `session_id` and `seq` to the kernel record.

Source documents: design spec section 24 (frames 24a, 24b, 24i, 24j, 24k), ROADMAP-2026-11-09-code-editor-r4.md, WORKING_AGREEMENT.md, the existing vocabulary at v0.27.

---

## Layer 0 — Ontology

One entity added: **EditorView**. Home: app. Join key: `pane_id`. Definition: the code editor view in a pane, holding the file tree, tab row, CodeMirror instances (via the widget registry at `web/app/widgets.ts`), inspector spine, column layout, quick open, and workspace search.

No separate OpenFile entity. The widget registry holds one `EditorView` per open file, but the trace does not identify individual files (E1 bars the path). The `tab_count` field on EDITOR_FILE_OPENED, EDITOR_FILE_CLOSED, EDITOR_CLOSED, and EDITOR_DRAWN is sufficient.

Dual classification: EditorView is an entity (Layer 0) and, through its EditorController, an operator (Layer 6). Same pattern as Pane/PaneController and Server.

## Layer 1 — Lexical

16 tags in a new `editor` category. 14 event stratum, 1 incident stratum, 1 view-category event.

**Lifecycle (2 tags).** EDITOR_OPENED carries the active `binding` (vim or nano). EDITOR_CLOSED carries `tab_count` at close. These open and close the `editor_run` session stratum.

**Files (3 tags).** EDITOR_FILE_OPENED carries `how` (tree, quick_open, follow, search, deep_link) and `tab_count`. EDITOR_FILE_SAVED carries `command` (vim_w, nano_save, menu_s) and pairs with FILE_WRITTEN on the server. EDITOR_FILE_CLOSED carries `tab_count`.

**Columns (1 tag).** EDITOR_COLUMN_FOLDED carries `column` (left, right, bottom) and `folded` (bool).

**Follow (3 tags).** A chain: EDITOR_FOLLOW_MARKED (at the tool-call event, carries `seq`) → EDITOR_FOLLOW_CONFIRMED (at the result, carries `seq` and `conflict`) or EDITOR_FOLLOW_WITHDRAWN (on failure, carries `seq`). State-transition rule S10 enforces the pairing.

**Inspector (2 tags).** EDITOR_HUNK_DRAWN carries `author` (session, hand, unattributed) and `line_count`. View-category tag: the rendered counterpart of the diff computation. EDITOR_INSPECTOR_SWAPPED carries `showing` (spine or lenses) for the ⌃⇧\` toggle.

**Chips (1 tag).** EDITOR_CHIP_ADDED carries `kind` (file, folder, range). No EDITOR_CHIP_REMOVED in this version; the removal is a UI action with no domain consequence on the record until the turn is submitted.

**Search (1 tag).** EDITOR_SEARCH_QUERIED carries `regex` (bool), `result_file_count`, and `result_match_count`. The query text stays out (E1).

**Quick open (1 tag).** EDITOR_QUICK_OPENED has no payload beyond the record context. The selection, if any, fires as EDITOR_FILE_OPENED with `how=quick_open`. No separate EDITOR_QUICK_COMMITTED — it would duplicate the file-opened tag.

**Incident (1 tag).** EDITOR_KEY_REFUSED carries `key` (the named key combo, as KEY_ROUTED) and `reason` (ended_session, view_only, binary_file, over_cap, no_git). Evidence constraint E9 (diagnostic-required).

**View (1 tag).** EDITOR_DRAWN carries the structural state: `tab_count`, `left_folded`, `right_folded`, `bottom_folded`, `binding`, `showing`, `left_tab` (files, search, open, activity). Written from the commit when any field differs from the last record. Pairs with every behavior tag in the dual contract.

## Layer 2 — Payload

All fields typed, all enums enumerated, no ambiguous requiredness. Every field is required (no optional fields on the new tags). The `seq` fields on the follow chain reference the kernel record's sequence number, satisfying E7 (cross-reference).

Two existing tags extended:
- PANE_DRAWN.state gains `editor` (P-0.28-PANE-DRAWN-EDITOR). The editor is a distinct visual state of the pane, not a sub-state of `session`.
- KEY_ROUTED.target gains `editor` (P-0.28-KEY-ROUTED-EDITOR). Menu keys like ⌘P route to the editor when it is open.

---

## Layer 3 — Session

One stratum added: **editor_run**. Open: EDITOR_OPENED. Close: EDITOR_CLOSED or PANE_CLOSED. Parent: pane. Persistent attribute: `binding`. Frames: editor-category tags of the pane.

The editor_run is a sibling of picker_run and pane_session under pane. A pane can have an active pane_session (the kernel session) and an active editor_run (the editor view) at the same time — the editor is a view over the session's workspace, not a replacement for the session.

---

## Layer 4 — Temporal

No new temporal invariants. The follow chain (EDITOR_FOLLOW_MARKED → confirmed or withdrawn) depends on the tool call's round-trip, which is unbounded (the model can take minutes). The ordering rule (S10) is sufficient; a timing window would false-positive on slow models.

---

## Layer 5 — State-Transition

Two rules added.

**S10** (pairing_ordering): EDITOR_FOLLOW_MARKED precedes exactly one EDITOR_FOLLOW_CONFIRMED or EDITOR_FOLLOW_WITHDRAWN for the same pane and seq. The chain has one entry and one exit.

**S11** (terminal): EDITOR_OPENED is the editor_run session's first record for a pane. No editor-category tag precedes it within the run.

---

## Layer 6 — Operator

One operator added: **EditorController**. Home: `web/app/editor/`. Emits all 16 editor tags. Responsibilities: file tree, tab row, editor instances (via widget registry), inspector spine (outline, changes, find, activity, history, info), columns, workspace search, quick open, follow marks, chips, diff vs main.

---

## Layer 7 — Evidence

One constraint added: **E9** (diagnostic_required on EDITOR_KEY_REFUSED). The `key` and `reason` fields provide the diagnostic. Mechanical enforceability: required fields.

E1 applies globally. Every new tag carries no path, no file text, no message text. The file's identity is reached through `session_id` + `seq` on the kernel record.

## Dual-contract audit

| Behavior tag | View-side counterpart | Notes |
|---|---|---|
| EDITOR_OPENED | PANE_DRAWN(state=editor) + EDITOR_DRAWN | Both fire on open; PANE_DRAWN gives the coarse state, EDITOR_DRAWN the structural detail |
| EDITOR_CLOSED | PANE_DRAWN(state=session) | Returns to the session view |
| EDITOR_FILE_OPENED | EDITOR_DRAWN (tab_count changes) | |
| EDITOR_FILE_SAVED | EDITOR_DRAWN + FILE_WRITTEN (server) | Cross-process pairing |
| EDITOR_FILE_CLOSED | EDITOR_DRAWN (tab_count changes) | |
| EDITOR_COLUMN_FOLDED | EDITOR_DRAWN (folded bools change) | |
| EDITOR_FOLLOW_MARKED | EDITOR_DRAWN | Modified dots or activity line become visible |
| EDITOR_FOLLOW_CONFIRMED | EDITOR_HUNK_DRAWN | The confirmed edit's hunk renders in the inspector |
| EDITOR_FOLLOW_WITHDRAWN | EDITOR_DRAWN | The mark disappears |
| EDITOR_CHIP_ADDED | EDITOR_DRAWN | The chip appears in the input bar |
| EDITOR_SEARCH_QUERIED | EDITOR_DRAWN (left_tab=search) | Search results visible in the left column |
| EDITOR_QUICK_OPENED | observation contract (screenshot) | The overlay is visible; no dedicated view tag — the overlay is transient and its structure is flat (a text input and a list) |
| EDITOR_INSPECTOR_SWAPPED | EDITOR_DRAWN (showing changes) | |

EDITOR_HUNK_DRAWN and EDITOR_DRAWN are themselves view-category tags. EDITOR_KEY_REFUSED is an incident, not a behavior; no view-side pairing required.

**Accepted gap:** EDITOR_QUICK_OPENED has no dedicated view tag. The quick-open overlay is a transient modal with one text input and one list. Its visibility is checked by the observation contract's screenshot track, not by a structural payload. If a future version needs a richer quick-open trace (keystroke-level fuzzy matching, result ranking), a view tag can be added then.

## Agent-resolved decisions

All recorded as agent-resolved entries on BLACKBOARD.md 2026-11-09.

1. **No EDITOR_CHIP_REMOVED tag in v0.28.** Removing a chip is a UI action with no domain consequence until the turn is submitted; TURN_ACCEPTED.attachments (v0.27) already captures the final count. Revisit if: the trace needs to distinguish a chip removed before send from one never added.

2. **No EDITOR_QUICK_COMMITTED tag.** The selection fires as EDITOR_FILE_OPENED(how=quick_open). A separate tag would duplicate the file-opened event. Revisit if: quick-open dismissal (no selection) needs its own tag.

3. **No temporal invariant on the follow chain.** The tool call's round-trip is unbounded. S10 (ordering) is sufficient. Revisit if: a maximum follow-mark duration is defined.

4. **PANE_DRAWN.state=editor is a new enum value, not a sub-state of session.** The editor's visual is completely different from the terminal transcript. A trace reader filtering by state needs to distinguish them. Revisit if: a third "view within a pane" appears and the enum grows unwieldy.

5. **EDITOR_FILE_SAVED.command distinguishes three save paths.** vim_w, nano_save, menu_s. The binding mode is already on EDITOR_OPENED and EDITOR_DRAWN; the command field names the specific trigger. Revisit if: additional save triggers appear (e.g., auto-save, which the roadmap's save policy rules out).

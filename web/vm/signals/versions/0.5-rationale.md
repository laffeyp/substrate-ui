# v0.5 rationale — reveal shell vocabulary

v0.5 makes the five `spec` tags live again. The other thirty-three of v0.4's tags carry over unchanged. v0.4 stays as written and locked.

## Live again: the `spec` tags

`SPEC_VALIDATE_REQUESTED`, `SPEC_VALIDATED`, `SPEC_BUILD_REQUESTED`, `SPEC_BUILD_REJECTED` and `SPEC_BUILT` fire around `SessionController.validateSpec` and `buildSpec`, which Studio's validate and build buttons call. v0.4 retired them when sprints 242–244 removed Studio and those two methods. That removal was a change a refactor may not make: the shell-to-React move was to change nothing the user can see or do (BLACKBOARD, 2026-11-05, the user's entry and the failure entry). Sprint 334 restored Studio, its button and both methods, so the tags fire again from the same code. Each takes back its v0.3 entry as written: name, category, stratum, payload and note, with no `retired` mark.

The server still has no `/api/validate` or `/api/build`. Studio's page is inert ("coming soon…", dimmed, no pointer), as it was before sprint 242, so nothing reaches those calls from the window; the tags are declared because the code that emits them is there, as in v0.3.

## Self-review

- Every tag the code emits is declared and live: `npm run signals` passes.
- The change is the reverse of v0.4's `TAG_DEPRECATION_PROPOSED` for these five tags, decided by the user (BLACKBOARD, 2026-11-05: every removal is undone).

# v0.34 rationale — saving, and the stale save

*2026-11-09, sprint 425. Bumps v0.33 to v0.34 (137 tags, 136 live). Two proposals: P-0.34-KEY-REFUSED-SAVE, P-0.34-SAVE-CONFLICT.*

## Layer 1 — Tags

EDITOR_SAVE_CONFLICTED: a save from the editor was refused because the file changed on disk since the buffer read it (the server's 409); the buffer is kept and the offer to reload or overwrite is drawn. EDITOR_CONFLICT_RESOLVED (choice reload | overwrite): the offer answered.

## Layer 2 — Payload

EDITOR_KEY_REFUSED.reason gains `not_editor` (⌘S outside the editor) and `no_file` (⌘S or ⌘W in the editor with no file open), as roadmap r8's key table asks ("refused, written"). EDITOR_DRAWN gains `conflict`. The anchor's third row takes a new layout with the conflict bit (magic 0xB7).

## Dual-contract pairing

| Behaviour | View-side counterpart |
|---|---|
| a save (EDITOR_FILE_SAVED; FILE_WRITTEN on the server) | EDITOR_DRAWN.unsaved falls |
| a stale save (API_REFUSED files 409; EDITOR_SAVE_CONFLICTED) | EDITOR_DRAWN.conflict true |
| the offer answered (EDITOR_CONFLICT_RESOLVED) | EDITOR_DRAWN.conflict false |

# v0.9 rationale — what a rejected signal says; two corrections (sprint 355)

*Locked 2026-11-06. Supersedes `0.8.json`; still 88 tags. Plan `process/planning/2026-11-05-sdd-signals/`, item 3: every process checks each signal where it is spoken. `0.8-rationale.md` and `0.7-rationale.md` remain the rationale for everything not named here.*

## The changes

Five proposals in `../proposals.json`.

**`P-0.9-FIELD-SIGNAL_REJECTED`** (`PAYLOAD_FIELD_PROPOSED`). The checkers enforce each field's declared type and evidence rule E5's ranges, so `SIGNAL_REJECTED.problem` gains `wrong_type` and `out_of_range` beside `unknown_tag`, `missing_field` and `extra_field`. It also gains an optional `field`, the payload field at fault. Without it, a reader of a `missing_field` rejection has to guess which of the tag's fields broke.

**`P-0.9-E4-STORE_SCANNED`** (`INVARIANT_PROPOSED`). v0.8 moved the store's counts from `SERVER_STARTED` to `STORE_SCANNED` but left evidence rule E4 asking `SERVER_STARTED` for outcome counts. The 0.8 rationale wrongly said no other rule changed. E4 now names `STORE_SCANNED`. E5's target, which said "ms", now names its fields exactly: `port`, `pid`, `count`, `seq`, `turn_index`, `proc_seq`, and fields ending in `_ms`.

**`P-0.9-TYPE-RUN_FOCUS_REQUESTED`** (`PAYLOAD_FIELD_PROPOSED`). `RUN_FOCUS_REQUESTED.sessions` was typed "int or list". `/run focus` sends the run's session list on every path (`web/vm/session_controller.ts`, `RunSessionRow[]`), and no checker reads a two-type union, so every emit of the tag would have been rejected. Found by the linter this sprint adds.

**`P-0.9-TYPE-TURN_INTERRUPTED`** and **`P-0.9-TYPE-SPEC_BUILT`** (`PAYLOAD_FIELD_PROPOSED`). Two more fields typed by their names in sprint 350 rather than by what their emit sites send. `TURN_INTERRUPTED.signal` is a boolean (true for Ctrl+C), not "string or null"; `harness/shakeout/copy_key.ts` found it, with two `SIGNAL_REJECTED` in its trace. `SPEC_BUILT.status` is the run's state as a string, not an HTTP status. An audit of all 66 emit sites with literal tags against their declared types found it. The audit found no other mismatch.

## The checker

One specification, `../checker-cases.json`, holds the rules and 23 cases. The window (`web/vm/instrumentation/check.ts`), main (`electron/check_signal.js`) and the server (`server.py` `_check_signal`) implement it, and each runs the cases in its own tests. Checks run in order, and the first failure is the answer:

1. an unknown tag;
2. a missing required field;
3. a field not declared (strict extras);
4. a value that does not match its declared type;
5. a number outside E5's range.

A long reason is cut by E2 (200 code points, marked `…[cut N]`).

**Posture (E6), sharpened.** A broken emit is written as `SIGNAL_REJECTED` in every build, and the broken record is not. A source or test build then raises; the packaged app goes on. Writing the rejection in every build keeps it in the trace even where a caller swallows the raise. The gate launcher (`harness/shakeout/lib/electron.ts`) fails any run whose trace holds one.

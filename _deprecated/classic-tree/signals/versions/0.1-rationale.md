## Intent and scope

Substrate-ui is a browser reader UI over the substrate runtime's records. It also hosts an agent terminal that POSTs `/api/agent` and polls the resulting record. This vocabulary covers what the user does (clicks, tab switches, chat turns) and what the UI paints in response (pane renders, inspector updates). It does NOT model substrate the runtime — that runtime has its own record + vocabulary and this UI reads them.

Scope bounded: the eleven categories carry every user-observable state transition in the current `web/app.ts`. Future expansion happens by supervised proposal, not silent addition.

## Per-layer decisions

**Layer 0 — Ontology.** The reader-UI ontology is not the runtime's. Entities: Session (the browser tab from open to close), Record (a substrate run selected in the rail), Assay (an assay report), View (which projection is active), Cursor (seq position in replay), Terminal (the chat dock), Turn (a chat turn), AgentRun (a launched agent session tied to a record), Topology (a bundled or authored topology), Diff (a comparison between two records).

**Layer 1 — Lexical.** 42 tags, verb-past-participle where possible. Deviations from that convention: `SESSION_INIT` and `RECORDS_LOADED` follow Katybird's precedent for state-establishing signals (init / loaded reads more natural than started / -ed for these).

**Layer 2 — Payload.** Every tag's payload is minimal-but-complete per technique #6. Reconstruction test: given a `RECORD_SELECTED{name, prior_name}` plus the resulting `RECORD_LOADED{name, event_count, status}`, a reader knows which record became active, what it displaced, how big it is, and whether it's live or done — enough to reconstruct the transition without the DOM.

`view_payload_universal` is `{frame, visible, pane_id, subject_record}` — deviates from the kit's template (which suggests `frame, visible, scene_id, layer` for game UIs). `scene_id` and `layer` don't fit a reader UI's rendering model. `pane_id` names which pane repainted; `subject_record` is the load-bearing invariant carrier for the subject rule ("every read-tab render for this record cites this record").

**Layer 3 — Sessions.** Two nested sessions: the outer `session` (browser tab lifecycle, bounded by `SESSION_INIT` → `SESSION_ENDED`); the inner `chat` (bounded by `CHAT_ENTERED` → `CHAT_EXITED`, but the conversation state persists across cycles for reconnect). SESSION_INIT carries the vocab_version so future replays can assert version parity.

**Layer 4 — Temporal.** Two named cadences: transport play at up to STATE.speed frames-per-second (window invariant on CURSOR_MOVED emission rate during PLAY_STARTED..PLAY_STOPPED); agent poll at ~500 ms (POLL_TIMEOUT fires when a run exceeds its ceiling without terminal-event). Neither category has an `ambient` stratum tag today — this UI doesn't sample continuous state.

**Layer 5 — State transitions.** Eight invariants stated (see `## invariants` in the JSON). The load-bearing ones: RECORD_SELECTED must be followed by RECORD_LOADED with matching name (staleness guard); AGENT_LAUNCHED must be followed by 1..N AGENT_TURN_STREAMED and terminated by exactly one FINAL_ANSWER_RENDERED or POLL_TIMEOUT with the same run_name; TURN_SUBMITTED only fires inside a CHAT_ENTERED..CHAT_EXITED window.

**Layer 6 — Runtime / Operator.** Not populated. Substrate-ui is a browser UI, not an operator chain. The kit's Layer 6 is optional per-project.

**Layer 7 — Evidence.** Every view-category tag carries the `view_payload_universal` structural fields — the mechanical check surface for the Rubber Duck Pass. Every incident-stratum tag (FETCH_FAILED, LAUNCH_REJECTED, POLL_TIMEOUT) carries a diagnostic payload (endpoint + status, kind + reason, run_name + elapsed) sufficient for a reader to act on. Tonal constraints: n/a in this pass — the UI's user-facing strings live in the DOM rendering code, not the signal payloads.

## Categories and why

- **session** — browser lifecycle. 2 tags.
- **records** — the rail. Load, select, prune. 3 tags.
- **record** — per-record fetch chain. 2 tags.
- **assay** — assay list + report. 3 tags.
- **view** — view toggle, cursor, transport, per-pane render. 9 tags (5 controls, 5 renders — GRAPH/TOPOLOGY/SCENE/IO/HEALTH_RENDERED).
- **stream** — event stream reads + inspector opens. 3 tags.
- **terminal** — dock chrome + chat mode + params. 6 tags.
- **agent** — chat turn lifecycle from submit to final answer. 5 tags.
- **topology** — launch, resume, studio nav. 5 tags.
- **diff** — diff pick + render. 2 tags.
- **incident** — failures. 3 tags.

## Dual-contract audit table

Every behaviour-category tag pairs with either a view-category tag (via the pane it triggers) or a structural payload field on a related tag. Load-bearing pairings:

| Behaviour | View-side counterpart |
|---|---|
| RECORD_SELECTED | GRAPH_RENDERED, TOPOLOGY_RENDERED, SCENE_RENDERED, IO_RENDERED, HEALTH_RENDERED, STREAM_RENDERED (all with matching subject_record) |
| VIEW_SWITCHED | one of GRAPH_RENDERED / TOPOLOGY_RENDERED / SCENE_RENDERED / IO_RENDERED with the new view's pane_id |
| CURSOR_MOVED | STREAM_RENDERED at the new seq |
| EVENT_INSPECTED | inspector DOM update (no separate view tag — the inspector is a fixed pane, its content follows the click) |
| MODEL_SELECTED, PARAMS_CHANGED | terminal chrome update (same — no separate view tag) |
| AGENT_TURN_STREAMED | termbody lines appended (checked by DOM assertion, not signal) |
| DIFF_REQUESTED | DIFF_RENDERED with matching a/b |

**Gap surfaced for future consideration:** inspector opens (EVENT_INSPECTED / PRODUCER_INSPECTED) don't have a paired render tag. If the inspector's paint becomes non-trivial (e.g., adds sub-panes), promote to INSPECTOR_RENDERED.

## Project-specific overrides

- **view_payload_universal** deviates from the kit template — `pane_id` + `subject_record` instead of `scene_id` + `layer`, per the reader UI's actual rendering shape.
- **Validator-extras posture:** strict. Unknown payload fields raise at the emitter, not documentation-only. Substrate-ui is small enough that strict-first pays back.
- **No Layer 6 operators.** Browser UI, not an operator chain.

## Open proposals for v0.2

Named for the Architect's later ratification:

- `NEW_TAG_PROPOSED: INSPECTOR_RENDERED` — if the inspector's paint gains sub-panes worth grading separately.
- `NEW_TAG_PROPOSED: FRAME_RENDERED` — a sampled ambient-stratum tag if the UI ever needs to grade paint cadence (currently no evidence it does).
- `PAYLOAD_FIELD_PROPOSED: TURN_SUBMITTED.turn_index` — currently optional; likely promotes to required once multi-turn observation matters.
- `TAG_SPLIT_PROPOSED: TOPOLOGY_LAUNCHED vs BUNDLED_LAUNCHED vs AUTHORED_LAUNCHED` — if bundled/authored paths diverge enough to warrant separate observation.

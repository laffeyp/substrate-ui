# Rationale — signal vocabulary v0.3

*New file per no-in-place-edits. `0.2-rationale.md` stays on disk. v0.3 folds the Architect's 2026-08-16 correction: substrate-ui is one thing, not two; the studio surface must be instrumented under the same discipline as the console. Sprint 032 landed the wiring.*

---

## Per-change ledger (v0.3 vs v0.2)

### 1. New category — `studio`

Placed between `diff` and `incident` in the category list. Groups the nine new tags below.

### 2. Nine new tags

| Tag | Payload | Stratum | Note |
|---|---|---|---|
| `SPEC_ROW_ADDED` | `{kind}` | event | User added a row on the authoring form. Enum kind: producer, view, trigger, route, member. |
| `SPEC_ROW_REMOVED` | `{kind}` | event | User removed a row via its .rm affordance. Same enum. |
| `CANVAS_TOGGLED` | `{to}` | event | Form ↔ canvas view toggle. to is form | canvas. |
| `SPEC_VALIDATE_REQUESTED` | `{}` (opt topology_name) | event | User clicked validate; the spec POSTs to /api/validate. |
| `SPEC_VALIDATED` | `{valid}` (opt error) | summary | Response landed. |
| `SPEC_BUILD_REQUESTED` | `{}` (opt topology_name) | event | User clicked build; validates then POSTs /api/build. |
| `SPEC_BUILT` | `{run_name, status}` (opt unfired_triggers_count) | summary | Build succeeded; a real record exists. run_name is a substrate Run identity. |
| `SPEC_BUILD_REJECTED` | `{reason}` | incident | Build failed at validation or execution. |
| `CONSOLE_LINK_FOLLOWED` | `{run_name}` | event | User clicked the "view the run in the console" link after a successful build. |

Total tag count: 53 (44 from v0.2 + 9).

### 3. Two new invariants

- `SPEC_VALIDATE_REQUESTED` is followed within 5 s by exactly one `SPEC_VALIDATED`.
- `SPEC_BUILD_REQUESTED` is followed within 30 s by exactly one `SPEC_BUILT` or `SPEC_BUILD_REJECTED`.

Same shape as the console's `RECORD_SELECTED → RECORD_LOADED` and `AGENT_LAUNCH_REQUESTED → AGENT_LAUNCHED` pairings.

### 4. Entity_merges — `Spec ↔ authored_topology`

The studio's `buildSpec()` returns an untyped author's-intent dict. `/api/validate` types it as a msgspec Struct; `/api/build` instantiates it via `builder.py`. Filed alongside the four v0.2 entity_merges.

### 5. Emitter, loader, and gates carry unchanged

The parity gate now scans the same `web/` + `harness/` tree it already scanned; `studio.ts` gains the emit import; the emit function code is unmodified. Two harnesses now, two fixtures: `captures/sprint-021/console.jsonl` (37 tags in expected order, unchanged) and `captures/sprint-021/studio.jsonl` (10 tags in a new studio-specific expected order). `npm run signals` chains both captures + both grades.

## What did NOT change

- The 44 v0.2 tags. Every one still fires at its console call site with the same shape.
- The v0.2 category renames (`view` → `pane`), payload_types on inspector tags, external_vocabulary_ref, runtime_operators.
- Any grader logic for the console fixture. Studio-specific checks live in a distinct `checkStudioPairings` function and a distinct EXPECTED_ORDER_STUDIO array.
